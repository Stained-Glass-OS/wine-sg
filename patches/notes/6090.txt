6090 uxtheme (found while chasing d0011): UXTHEME_ApplyColorScheme (the light/dark/Rounded/era scheme switch from RefreshImmersiveColorPolicyState, 0160 and later) wrote every [SysMetrics] colour of the new scheme to HKCU\Control Panel\Colors and SetSysColors, COLOR_BACKGROUND included (light.msstyles' schemes all say 37 111 149), so a solid desktop colour chosen in Settings was lost at each app-mode switch. Now COLOR_BACKGROUND is dropped from the scheme's list before saving and applying. The first theme activation (UXTHEME_SetActiveTheme with metrics, at prefix creation) still sets the default 37 111 149.
d0011 itself (test-layeredblend failing on the full series) was a harness problem, fixed in e8ffb357 (10.0-577): in a build tree "wineserver -w" ran a non-existent <loader>/wineserver, so wineboot's session -- with the theme colours its 32-bit Wow64Install rundll32 set in the volatile sysparams -- ran on into the test.
Gate: test-schemedesktop (magenta desktop set as Settings does; dark then light: the scheme's colours change, the desktop's and the saved one stay). Mutant SG_MUTANT_SCHEME_SETS_DESKTOP caught (the desktop went 37,111,149). darkmode, explorer-dark, desktopbg gates pass.
