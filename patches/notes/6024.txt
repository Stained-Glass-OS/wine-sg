6024 server/win32u SH-DPI (ledger i0110): the DPI awareness of another process. A process's DPI awareness context lived only in its own memory, so GetDpiAwarenessContextForProcess/GetProcessDpiAwareness of another process said "unaware" and GetSystemDpiForProcess said 0 (FIXME). NtUserSetProcessDpiAwarenessContext now records the context in the server (new request set_process_dpi_context), and NtUserGetProcessDpiAwarenessContext of another process reads it (get_process_dpi_context, PROCESS_QUERY_LIMITED_INFORMATION; a process that set none is unaware; an inaccessible handle gives 0); NtUserGetSystemDpiForProcess of another process: 96 for an unaware one, the system DPI otherwise. Protocol change: every unix module is rebuilt with it.
Docs: learn.microsoft.com GetDpiAwarenessContextForProcess, GetProcessDpiAwareness, GetSystemDpiForProcess.
