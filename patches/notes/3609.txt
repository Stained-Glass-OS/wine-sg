hidclass (3609): winedevice "Unhandled page fault ... IoCompleteRequest" fix (REGRESSION SWEEP follow-up). Culprit that exposes it: 2223 (services get SERVICE_CONTROL_SHUTDOWN, winedevice removes devices at shutdown; stock kills services so the path never ran). Mechanism: hid_device_thread's IOCTL_HID_READ_REPORT IRP had UserIosb/UserEvent on the thread stack; on removal the thread leaves with the IRP pending in winebus, which completes it with STATUS_DELETE_PENDING (remove_pending_irps) after the thread stack is freed. Also plugplay is already stopped then (RPC_S_SERVER_UNAVAILABLE warnings from send_devicechange: harmless, caught).
Fix: io+event in a heap block, kept (not freed) if the IRP may still be pending at thread exit (a few bytes per removed device).
Gate test/fastb-hidstack-gate.sh: 40 sessions 0 faults; before the fix 8/40 (stock 0/60); mutant SG_MUTANT_HID_STACK_IO 8/40.
Unverified: the hidclass winetest.sys driver tests (need an installed test driver); a bus driver other than winebus that completes the IRP after removal is covered the same way.
