CORE review: behaviour change
 - Installer.OpenDatabase: a numeric OpenMode (msiOpenDatabaseModeCreate = 3 ...) is now passed as the MSIDBOPEN_* persist constant. It was converted to the string "3" and used as an OUTPUT FILE NAME, so Create/Direct modes never worked from scripts. A string mode is passed as before.
 - MsiEnumProductsEx: the szProductCode filter compared the GUID with the SQUASHED registry key name and never matched; it now squashes the GUID first (an invalid GUID gives ERROR_INVALID_PARAMETER, new). Wine's tests only call it with an unregistered product.
 - MsiSourceListEnumMediaDisks skipped nothing: the values MediaPackage and DiskPrompt of the Media key were returned as disks 0 with garbage; only values named by a disk id are disks now.
 - MsiSourceListAddSourceEx, MsiSourceListSetInfo, msi_set_last_used_source and AddMediaDisk accept MSICODE_PATCH (they returned FIXME failures; ERROR_UNKNOWN_PATCH comes from OpenSourceKey as the existing tests expect).
 - msipriv.h cost_from_size: (size + 4095) overflowed int for sizes above 2 GB - 4095 (negative cost); computed in 64 bits.
 - publish_sourcelist during ACTION=ADVERTISE sets LastUsedSource to the folder of the package, so an advertised product can be reconfigured or removed from the advertisement alone (ConfigureProduct(absent) failed with no source). Normal installs unchanged.
 - Installer.LastErrorRecord and Database.LastErrorRecord return MsiGetLastErrorRecord (always Nothing before).
 - New failure paths: Session.VerifyDiskSpace is false (ERROR_DISK_FULL) when a drive cannot hold the costed installation; MsiEnumProductsEx(invalid GUID). No UI is added at any UILevel (UIPreview is an explicit authoring preview).
