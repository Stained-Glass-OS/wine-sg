CORE review: security. SHIPPED HOLE: candidate for an early release (any user of a shared prefix could add an all-users autostart, change the system version keys, services' parameters of keys loaded from system.reg ...). Reported by the coordinator's request after the 3756 finding; analysis in /var/tmp/stubs-agent/HKLM-TOKEN.md.
Cause: check_object_access() returns TRUE for an object without a security descriptor; keys loaded from system.reg have none (descriptors are not persisted); sg-session's sg_protect_machine_registry stamps two Policies branches only; keys created at runtime get the creator's default DACL, so which HKLM keys were protected depended on whether they were made before or after the last server start. Verified as the real standard user sgtest1 in a shared system prefix restarted as at boot: it created HKLM\Software\X and set values in Software\Microsoft, Windows NT\CurrentVersion, ...\CurrentVersion\Run, Session Manager and Software\Wine.
Server (server/registry.c sg_key_default_sd, server/token.c sg_machine_key_sd + check_object_access): in a system prefix a key at or under \Registry\Machine with no descriptor is checked against SYSTEM GA, Administrators GA, Users GR, Authenticated Users GR, RESTRICTED GR, ALL APPLICATION PACKAGES GR (all container-inherit) and CREATOR OWNER GA (inherit only), the same readers 0248 gives new keys. The check applies to open (handle access), to creating below such a key (GENERIC_WRITE on the container, object.c) and to the key_get_sd answer of GetSecurityInfo. Restricted and write-restricted tokens go through the same token_access_check as before (denied: gate). Exemptions, each found by tracing standard-user sessions with SG_TRACE_MKEY_DENY=1 (usersessions, dispcfg, displaycfg, sandboxdesk, wtstoken, stduserprint gates and 20 console programs): the existing display configuration names (Control\Video, GraphicsDrivers, DEVICEMAP\VIDEO, Enum\PCI, Enum\DISPLAY, Class\{4D36E968..}/{4D36E96E..}, the font list) plus Control\DeviceClasses\{E6F07B5F-EE97-4A90-B076-33F57BF4EAA7} (monitor), {5B45201D-F2F2-4F3B-85BB-30FF1F953599} (display device arrival) and {1CA05180-A699-450A-9A0C-DE4FBE3DDD89} (display adapter): the display setup of every session writes them (asked KEY_WRITE). What is still denied to a user and was open before, deliberately: Control\Nls\Codepage ACP/OEMCP/MACCP writes (locale.c tries KEY_ALL_ACCESS to refresh them), HKLM\Software\Classes registrations through HKCR (the HKCR view already falls back to the user's classes), everything else under HKLM. Not traced: a session with a real X11/Wayland driver, other applications: the escape hatch is the exemption list and SG_TRACE_MKEY_DENY=1.
ntdll/version.c: RtlGetVersion read HKLM CurrentVersion/Control\Windows/ProductOptions with KEY_ALL_ACCESS (found by the trace: the key would be unreadable for users and every process fell back to the built-in version).
kernelbase/registry.c virtualization (see the comment at virt_enabled): Windows' UAC rules as documented: only HKLM\Software, not Classes, Microsoft\Windows, Microsoft\Windows NT; only 32-bit processes without a requestedExecutionLevel (RtlQueryInformationActivationContext RunLevel of the active context, unspecified); not elevated, not SYSTEM, GUESS: Windows also virtualizes a non-elevated Administrator with a filtered token, here a member of Administrators writes directly (no linked token model, and it keeps the conformance suites, which run as the prefix owner, unchanged). A write that is denied (open with write access, create) is made in HKCU\Software\Classes\VirtualStore\MACHINE\SOFTWARE\[Wow6432Node\]path; an open that fails because only the store has the key returns the store's key; a read-only open of a machine key whose store twin exists is merged (store first for values, subkeys and values of both). Implemented on top of the HKCR merged view (tracked path begins with a backslash); the A/W create and open entry points. Not done: REG_KEY_DONT_VIRTUALIZE / DONT_SILENT_FAIL / RECURSE flags of NtSetInformationKey (the key flags are not persisted by our server), virtualization of key deletion and security calls, services and session 0 (Windows disables it there; our services run as SYSTEM, which is exempt), the Nt* calls made directly. SG_REGISTRY_VIRTUALIZATION=0 switches it off, =1 forces it for tests. The state is decided once per process (the first use), the run level of the active context at that time.
Gate test/hklmsd-gate.sh (Makefile test-hklmsd; sudo + sgsystem/sgtest1/sgtest2): 33 checks; mutants caught: server MKEY_NODEFAULT (14 failures), MKEY_AU_WRITE (Authenticated Users get write: 14), kernelbase VIRT_ANY_LEVEL (manifested program virtualized: 2), VIRT_64BIT (64-bit virtualized: 6), VIRT_NOT_EXCLUDED (Windows NT virtualized: 4), VIRT_NO_STORE_READ (reads do not see the store: 3).
