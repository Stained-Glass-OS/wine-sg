8702 dlls/win32u/menu.c draw_bitmap_item -- apps10 (TuxGuitar 2.1.1 on qa4: every menu icon in a black square).
Cause: SWT's MenuItem.setImage gives hbmpItem a premultiplied 32 bpp DIB section; win32u BitBlt'ed it, so alpha-0 pixels (0,0,0,0) came out black. Windows (Vista and later) blends 32 bpp menu bitmaps with alpha.
Fix: menu_bitmap_has_alpha() -- 32 bpp, bmBits (DIB section), any alpha byte != 0 -- then NtGdiAlphaBlend(AC_SRC_OVER, 255, AC_SRC_ALPHA) of min(item, bitmap) size; otherwise BitBlt as before (also the NOTSRCCOPY inversion of highlighted plain bitmaps). Magic bitmaps unchanged. Verified on qa4 with the patched win32u.so: TuxGuitar's Measure menu icons drawn cleanly, highlighted item too.
Gate menualpha (test-menualpha, Xvfb :312): popup menu with two bitmap-only items read back from the menu window: item 0 (red 8x8 opaque in a transparent 16x16) gives 0 black pixels and 64 red (old: 192 black); item 1 (32 bpp, alpha 0, blue) stays 256 blue. Mutant SG_MUTANT_MENU_BITMAP_NO_ALPHA. btnmenu, embedmenu, menubg, menukeep, traymenu, win32u-menu-autodismiss pass.
