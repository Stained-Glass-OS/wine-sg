5210 user32/sechost: device events for ANSI windows (gap-CORE 656).
Docs: learn.microsoft.com/en-us/windows/win32/api/dbt/ns-dbt-dev_broadcast_port_a (the ANSI/wide pair; dbcp_name is the only string), DEV_BROADCAST_VOLUME / NET / DEVNODE / OEM (no strings).
devnotify_window_callbackA converted DEVICEINTERFACE and HANDLE events and FIXMEd on every other type. It now converts DBT_DEVTYP_PORT (dbcp_name wide to ANSI, size rewritten, a name lacking its terminator is cut at the structure size) and passes the structures without strings (OEM, DEVNODE, VOLUME, NET) as they are, without the FIXME.
sechost I_ScRegisterDeviceNotification: the notification record was allocated with the filter's size only, but the matcher reads a DEV_BROADCAST_HDR from it; for the empty filter RegisterDeviceNotification passes (size 0) that was a heap over-read and made "no filter" match by chance. The record now always has room for the header (zero = matches every event).
Unverified: nothing in Wine sends PORT/VOLUME/NET/DEVNODE events by itself (plugplay only sends interface and handle events), so the new conversion is reached only by an event injected through the plug-and-play RPC interface (as the gate does) with a registration that has no filter; real Windows broadcasts those types to every top-level window instead.
