6077 webservices (N-WEBSERVICES). WsCreateFaultFromError, WsSetFaultErrorDetail and WsSendFaultMessageForError were stubs: a WWSAPI service could not answer a failed operation with a fault. From the MS docs pages of the three functions and WS_FAULT_DISCLOSURE.
- WsCreateFaultFromError (error.c): the error's own fault (WS_FAULT_ERROR_PROPERTY_FAULT) when it has one, else a generic fault; a missing code gets the generic one (picked: SOAP 1.2 env:Receiver); no reason -> full disclosure: the error strings oldest first joined by spaces, else the failure code's text (same table/FormatMessage as set_error); minimal disclosure: a generic text (picked wording); reason language from WS_ERROR_PROPERTY_LANGID (LCIDToLocaleName). E_INVALIDARG: success code, no error/heap/fault, bad disclosure.
- WsSetFaultErrorDetail: writes <detail> with the element (or a struct's fields when the element has no name; REQUIRED_VALUE/POINTER only) into the error's fault (created if none), sets the action when given.
- WsSendFaultMessageForError (channel.c): WsCreateFaultFromError, action = the error's fault action or the WS-Addressing fault action of the message's addressing version, body Fault in the envelope's namespace; sent like WsSendReplyMessage but initialized as WS_FAULT_MESSAGE and marked IS_FAULT (HTTP 500). The error's fault header (WS_FAULT_ERROR_PROPERTY_HEADER) is not added.
- Fixes: receive_message returned WS_E_INVALID_FORMAT for a fault reply (tried the next description); now WS_E_ENDPOINT_FAULT_RECEIVED, channel not faulted. writer: standard fault codes mapped between versions (SOAP 1.1 Client/Server <-> SOAP 1.2 Sender/Receiver, DataEncodingUnknown -> Client), other code namespaces declared (xmlns:fc); the detail written as the version's element (1.1 detail, 1.2 env:Detail) with its children. WsGetFaultErrorDetail accepts the 1.2 Detail.
- Seen, not fixed: WsCopyNode from a buffer reader positioned on an element copied the start element only (the detail writer reads and writes node by node instead).
- Not done (other stubs): service host, metadata/policy, header understanding (WsGetHeaderAttributes/WsMarkHeaderAsUnderstood/WsCheckMustUnderstandHeaders need per-header state), WsRemoveNode (Wine's buffers are bytes, not trees), async/cancel helpers. Security tokens, WS-Security, canonicalization -> ESCALATE.
Gate: test-wsfault (unshare -rn; HTTP reply channel, SOAP 1.2 and 1.1). Wine's channel/msg/proxy/reader/writer tests pass. Mutants SG_MUTANT_WSFAULT_NO_STRINGS, SG_MUTANT_WSFAULT_NO_DETAIL caught.
