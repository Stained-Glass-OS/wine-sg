3723 amsi (gap-CLOUD). The four fake-success entry points are now a real AMSI client.
 - AmsiInitialize loads the antimalware providers registered as HKLM\Software\Microsoft\AMSI\Providers\{CLSID} (CoCreateInstance, IAntimalwareProvider; IIDs and vtable layout from windows-rs 0.58.0 Win32/System/Antimalware) and keeps the app name; AmsiUninitialize releases them. Contexts and sessions are real objects that handles are checked against (a bad handle is E_INVALIDARG, never a crash).
 - AmsiScanBuffer / AmsiScanString hand each provider an IAmsiStream over the buffer: GetAttribute for APP_NAME, CONTENT_NAME (only when a name was given), CONTENT_SIZE, CONTENT_ADDRESS, SESSION (too-small buffer: ERROR_INSUFFICIENT_BUFFER and the needed size), Read(position,size,...). Other attributes: E_NOTIMPL with a FIXME (ALL_SIZE/ALL_ADDRESS/REDIRECT_CHAIN_*/QUIET not supported). A string is scanned as its UTF-16 bytes. Result: the highest value any provider returns (CLEAN 0 < NOT_DETECTED 1 < BLOCKED_BY_ADMIN 0x4000.. < DETECTED 0x8000); no provider: AMSI_RESULT_NOT_DETECTED (as before); a provider that fails is skipped (GUESS: Windows' policy for a failing provider is not documented). NULL buffer/result, length 0, empty string, unknown context/session: E_INVALIDARG (GUESS for the details).
 - AmsiOpenSession numbers the sessions per context; AmsiCloseSession tells every provider (CloseSession(id)).
 - Not done: AmsiUac* (stubs), notifications (IAntimalwareProvider2). No provider ships with SG yet: wiring SG Defender (ClamAV) in as one is a follow-up.
Gate fastb-amsi (in-process fake providers registered through HKLM + CoRegisterClassObject). Mutants caught: SG_MUTANT_AMSI_NOSESSION, _NOPROV, _NOCLOSE, _ARGS, _MIN. dlls/amsi has no conformance tests.
