6034 msado15, msdasql (DB-ADO): commands with parameters. msado15 command_Execute returned adErrFeatureNotAvailable whenever the command had Parameters or Execute was given values; msdasql command_Execute never looked at DBPARAMS. Now execute_with_parameters() (command.c): the parameters (collection, else one input per element of the values array; values replace inputs in order and are stored in the parameters), a provider command from the connection's session, SetParameterInfo (DBTYPE names from the ADO types: adVarWChar -> DBTYPE_WVARCHAR etc., size, input/output flags), one DBTYPE_VARIANT binding per parameter (value, status, length) through IAccessor::CreateAccessor(DBACCESSOR_PARAMETERDATA), Execute(DBPARAMS), output/return values put back with _Parameter_put_Value, a rowset as a recordset (Recordset_open_rowset), the affected count; adCmdStoredProc is "{ [? =] call name(?, ...) }" (a first adParamReturnValue parameter is the return value); adOptionUnspecified (-1) means no options (it set adExecuteNoRecords). msdasql: the command has IAccessor (a rowtable of parameter accessors, rowset.c rt_find_accessor); params.c binds each accessor binding with SQLBindParameter: native types as their C types (I1..UI8, R4, R8, BOOL as BIT, GUID, DBDATE/DBTIME/DBTIMESTAMP/DATE as timestamps, STR, WSTR, BYTES; CY/NUMERIC/DECIMAL as text), a VARIANT as the type SetParameterInfo declared (else its own vt), NULL from DBSTATUS_S_ISNULL, lengths from the length part; output and input/output values (and their statuses, lengths) written back after execution, VARIANT outputs in the declared type. A statement gives a rowset when SQLNumResultCols > 0 (a procedure returning rows), not when its text begins with "select ".
