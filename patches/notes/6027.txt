6027 crypt32 (found by 6028's gate: a 32-bit caller of PackageManager): HKLM\Software\Microsoft\SystemCertificates is a shared key (wine.inf links the 32-bit view to it, as Windows shares it), but rootstore.c's record of the roots it imported from the host (HKLM\Software\Wine\Crypt32 ImportedRootCerts, patch 0042) is under Software\Wine, which WoW64 redirects. A 32-bit program read an empty record, so CRYPT_ImportSystemRootCertsToReg took every root in HKLM\Root for an imported one, and when the host sync then rewrote the store (a host root missing from the cache) the administrator's roots were deleted -- the first 32-bit program after a root was added removed it for everyone. The record is now opened with KEY_WOW64_64KEY for reading and writing.
Docs: learn.microsoft.com "Registry Keys Affected by WOW64" (SystemCertificates shared).
Gate rootwow (test-rootwow): a signed program does not verify before its root is added; a 64-bit program adds the root and verifies; the first 32-bit program verifies too; the root is still there for the 64-bit program after it, for the next 32-bit one, and after a server restart. Mutant caught: SG_MUTANT_ROOTS_WOW_VIEW (the per-view record): the first 32-bit program wipes the root, 4 checks fail.
Conformance vs before (64/32): crypt32 chain 0 = 0, store 0 = 0, cert 0 = 0.
