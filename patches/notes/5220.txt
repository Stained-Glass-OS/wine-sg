5220 win32u: D3DKMTQueryAdapterInfo, the types Wine has data for (gap-CORE 65, PARTIAL).
Docs: windows-driver-docs-ddi d3dkmthk nf-d3dkmtqueryadapterinfo ("STATUS_INVALID_PARAMETER: parameters were validated and determined to be incorrect"), ne-d3dkmthk-_kmtqueryadapterinfotype, ns-d3dkmthk-_d3dkmt_adaptertype / _segmentsizeinfo / _physical_adapter_count / _currentdisplaymode / _displaymode.
NtGdiDdDDIQueryAdapterInfo was a stub (STATUS_NOT_IMPLEMENTED for every type). Now: STATUS_INVALID_PARAMETER for NULL, adapter 0 or not open, no buffer, a buffer smaller than the output. Answered types: KMTQAITYPE_ADAPTERTYPE (render + POST + display when the adapter has the display), ADAPTERGUID (the Vulkan device UUID, else a fixed GUID made from the LUID; the same for the same adapter), PHYSICALADAPTERCOUNT (1), GETSEGMENTSIZE (Vulkan device-local heaps as dedicated video memory, other heaps as shared system memory; 0 without Vulkan), CURRENTDISPLAYMODE (size, format, refresh rate, orientation of the display source; the source id is numbered as NtGdiDdDDIOpenAdapterFromHdc returns it). The structures are declared privately in d3dkmt.c, not in the public headers (no full rebuild).
NOT done: every other KMTQAITYPE (UMDRIVERNAME / UMDRIVERPRIVATE / UMOPENGLINFO, ADAPTERADDRESS, ADAPTERREGISTRYINFO, MODELIST, DRIVERVERSION, WDDM_x_y_CAPS, ...) still logs the FIXME and returns STATUS_NOT_IMPLEMENTED: they carry values a hardware kernel-mode driver reports (PCI address, driver version, WDDM capability bits) that Wine has no data for; so this item is PARTIAL and escalated.
Unverified: bit positions of D3DKMT_ADAPTERTYPE (taken from the documented field order), D3DKMT_DISPLAYMODE field order/DisplayFixedOutput/Flags (0), the RGB format codes, that native reports the DedicatedVideoMemory the same way.
