6038 msado15, msdasql (found while checking 6037 with the SQLite ODBC driver): a SQLite TEXT column (SQL_WLONGVARCHAR, 65536) read as empty, and so would any memo/long column. msdasql flags such a column DBCOLUMNFLAGS_ISLONG. ADO's create_bindings binds it as DBTYPE_IUNKNOWN with pObject iid ISequentialStream. rt_create_accessor rejected a DBTYPE_IUNKNOWN binding that had pObject (BADBINDINFO, from 6011, which made pObject ignored for other types) and dropped every pObject. The accessor failed (0x80040E21) and the whole recordset was empty.
Now:
- rt_create_accessor accepts ISequentialStream/IStream storage objects (others are DBBINDSTATUS_NOINTERFACE) and keeps them in acc->objects.
- rt_get_data gives an IStream over the cell's bytes (CreateStreamOnHGlobal), queried for the asked interface.
- rt_get_bindings returns CoTaskMemAlloc'd copies of the storage objects, as callers free them.
- msado15's stream reader grows its buffer for any read size (it overflowed when a read was shorter than 2048 and the total skipped past the buffer size).
- Long WSTR/STR/BYTES fields report adLongVarWChar/adLongVarChar/adLongVarBinary (203/201/205).
Gate adolong (test-adolong; the mock driver's SG_ADOMOCK_LONG=1 makes its Name column SQL_WLONGVARCHAR 65536). It checks: the value reads through Execute, Null is Null, the next rows read, the type is 203 with adFldLong, Recordset.Open works, and a long column is changed and written back.
Mutants caught: SG_MUTANT_DASQL_NO_STREAM (8 FAIL), SG_MUTANT_ADO_LONG_TYPE (1).
Real driver: SQLite ODBC TEXT column reads "Ann", Type 203.
Regression: gates adoodbc, adoparam, adoupdate, adorecords, adoconn, adocmd, adostream, fastado, fastado2, adoauth and fastmsdasql pass. Conformance vs before (64/32): msdasql provider 0=0, msado15 0=0.
