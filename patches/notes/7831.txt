7831 jscript, vbscript -- queue i0029 COM-SCRIPT ("engine interrupt polling"). The engines never asked the host IActiveScriptSiteInterruptPoll::QueryContinue, which Windows' engines call at intervals while a script runs (hosts use it for "stop running this script?"); a host relying on it could not stop a runaway script. Now: every 16384 instructions the interpreter checks the clock and, once a second of running has passed since the last question (from the top-level entry), QIs the site once (cached, reset on SetScriptSite/Close) and calls QueryContinue; S_FALSE raises the same interrupt as InterruptScriptThread without SCRIPTINTERRUPT_RAISEEXCEPTION (E_ABORT, aborting: no handler resumes it). msscript's Timeout (7723) already stops scripts via InterruptScriptThread and is unchanged (msstimeout passes).
Gate test-scriptpoll (64/32, JS and VBS): S_FALSE on the third question stops an endless loop after ~3 s (asked=3, hr 80020101); a host answering S_OK is asked and a 2.2 s loop completes; a host without the interface completes. Mutants JS_NO_INTERRUPT_POLL, VBS_NO_INTERRUPT_POLL caught. fastjsb1, fastvbb1, msstimeout pass; Wine jscript and vbscript conformance tests 0 failures.
