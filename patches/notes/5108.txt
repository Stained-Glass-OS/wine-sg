5108 ole32: STGM_CONVERT (gap-CORE item 499 GetCreationModeFromSTGM, "STGM_CONVERT not implemented"). The flag is 0x20000, outside the mask STGM_CREATE_MODE uses, so it was silently ignored (an existing file was STG_E_FILEALREADYEXISTS, as for STGM_FAILIFTHERE) and the FIXME case in GetCreationModeFromSTGM could never be reached.
StgCreateDocfile / StgCreateStorageEx with STGM_CONVERT now keep the existing file's bytes as the stream "CONTENTS" of the new compound file and return STG_S_CONVERTED (the return the old Wine comment on StgCreateDocfile records as "unrealized"); a file that is not there is created (S_OK); STGM_CONVERT with STGM_DELETEONRELEASE is STG_E_INVALIDFLAG. Docs: learn.microsoft.com/en-us/windows/win32/stg/stgm-constants ("Creates the new object while preserving existing data in a stream named Contents ... the old data is formatted into a stream regardless of whether the existing file currently contains a layered storage object. ... not valid with STGM_DELETEONRELEASE") and the STGM_CREATE+STGM_CONVERT check in validateSTGM.
Unverified: the stream name is spelt CONTENTS (older docs) — stream lookup is case-insensitive in compound files, the page says "Contents"; STG_S_CONVERTED as the success code (from the old Wine source comment, not a docs page); in transacted mode the docs say the conversion happens at Commit and the old file is restored if it is never committed — here the file is replaced at once, as STGM_CREATE does in this implementation; the old file is read into memory first (up to 2 GB).
