3236 webservices: write_type and read_type no longer answer E_NOTIMPL for three of the types they did not handle: WS_DURATION_TYPE (xsd:duration PnYnMnDTnHnMn.fffffffS, negative sign, milliseconds/ticks as the 7-digit fraction, WS_DURATION_DESCRIPTION range with the documented default comparer that compares years+months only or no-years/months only, the description's comparer used when given; also WS_DURATION_VALUE_TYPE for WsWriteArray/WsReadArray), WS_CUSTOM_TYPE (WS_CUSTOM_TYPE_DESCRIPTION read/write callbacks; the writer callback is called with the element already started, the reader callback reads the element itself, as the docs' WsReadType/WsWriteType calling sequences say; value/pointer/nillable options; field use in structs), WS_XML_BUFFER_TYPE (ELEMENT mapping: attributes and content of the buffer's root element replace those of the element being written; ANY_ELEMENT mapping writes the whole buffer; reading copies the element into a new buffer that keeps its name). include/webservices.h gains WS_TIMESPAN, WS_DURATION, their descriptions and WS_CUSTOM_TYPE_DESCRIPTION with WS_READ_TYPE_CALLBACK/WS_WRITE_TYPE_CALLBACK/WS_IS_DEFAULT_VALUE_CALLBACK/WS_DURATION_COMPARISON_CALLBACK (from the sdk-api pages).
NOT done (still E_NOTIMPL, the FIXME stays): WS_TIMESPAN_TYPE (its text form is not documented; the existing writer comment says the same), WS_ENDPOINT_ADDRESS_TYPE (needs WS_ENDPOINT_ADDRESS_DESCRIPTION, the WS-Addressing element layouts per version and the identity extension: the docs only list field correspondences), WS_CHAR_ARRAY/UTF8_ARRAY/BYTE_ARRAY (field-level types handled by the struct code, not by WsWriteType) and WS_ANY_ATTRIBUTES_TYPE (field-level). WS_IS_DEFAULT_VALUE_CALLBACK is accepted in the description but not called.
Gate fastwebtypes (test/fastwebtypes-gate.sh, builds against Wine's webservices.h) 84 checks 64/32; 17 mutants SG_MUTANT_WSD_/WSC_/WSX_* caught (work/muts-wsd.sh). webservices conformance: 6 units, 0 failures 64/32 (the older stock Wine has 57-63 failures in these tests).
GUESSES: a milliseconds >999 or ticks >9999 is WS_E_INVALID_FORMAT on write; digits of a fraction past the 7th are dropped; zero duration is written PT0S without sign; a value that overflows ULONG is WS_E_NUMERIC_OVERFLOW; the custom reader callback is called after the element was positioned, the callback consuming the start/end element itself.
UNVERIFIED: no Windows to compare; WsReadType (public) of a CONTENT mapping custom type fails because Wine's WsReadType requires the input to be at its end afterwards (pre-existing behaviour for every type, not changed).
