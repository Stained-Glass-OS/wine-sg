CORE review: rtworkq (Media Foundation's work queues; only reached through the two new functions, everything else is unchanged). Docs: learn.microsoft.com RtwqJoinWorkQueue ("associates a work queue with an I/O handle ... a cookie that represents the association"), RtwqUnjoinWorkQueue, and the MFASYNCRESULT / RTWQASYNCRESULT structure (overlapped, pCallback, hrStatusResult, dwBytesTransferred: the OVERLAPPED an I/O is started with is that of the async result).
How: one completion port and one thread for all joins (created at the first join, ended by RtwqShutdown). RtwqJoinWorkQueue(queue, hFile, &cookie) associates hFile with the port using the join's id as the completion key and hands the id back as the cookie; the queue is locked (a user queue lives on while joined). The thread dequeues a completion, finds the join by key, stores the status (HRESULT_FROM_WIN32 of the error, S_OK) and the byte count in the RTWQASYNCRESULT that contains the OVERLAPPED, and puts the result on the join's work queue (queue_put_work_item), whose callback is invoked there (a serial queue serializes them). RtwqUnjoinWorkQueue(queue, cookie) removes the join and unlocks the queue; unknown cookie or a cookie of another queue: E_INVALIDARG (GUESS: the code). Errors: NULL cookie E_POINTER, NULL or INVALID_HANDLE_VALUE E_INVALIDARG (GUESS), a queue that does not exist RTWQ_E_INVALID_WORKQUEUE, a handle that is not overlapped or is joined twice the Win32 error as an HRESULT.
Limits (GUESSES about the unspecified): a handle can not be taken out of a completion port again, so after the unjoin its completions are dropped, not delivered some other way; the OVERLAPPED must be the one of an RTWQASYNCRESULT (as on Windows: anything else is undefined); shutdown (the last RtwqShutdown) drops every join.
Gate fastb-rtwqjoin: argument errors, join / lock count / unjoin, an I/O completing with the right status and bytes on another thread, completions dropped after the unjoin, serial queue serializes (300 ms callbacks do not overlap) while a multithreaded one runs them together, a failing read (end of file) reports ERROR_HANDLE_EOF, shutdown with a join left; 12 mutants (11 caught; NO_QUEUE_CHECK is equivalent because the queue lookup after it gives the same error). Conformance 64/32 vs the series-applied base (3760): rtworkq identical (0 failures).
