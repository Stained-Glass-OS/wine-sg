8002 wbemprox/wbemdisp/wscript COM-WMI (gaps9 ledger i0061): WMI event queries. events.c: hand parser for SELECT * FROM <event class> [WITHIN s] [WHERE ...]; intrinsic __Instance{Creation,Deletion,Modification,Operation}Event need TargetInstance ISA 'X' (else WBEM_E_NOT_SUPPORTED; unknown X -> WBEM_E_INVALID_CLASS; PreviousInstance conditions -> WBEM_E_NOT_SUPPORTED), the rest of the WHERE minus "TargetInstance." becomes the polled data query; extrinsic Win32_Process{Start,Stop}Trace/ProcessTrace (names mapped to Win32_Process's, 200 ms poll without WITHIN), Win32_DeviceChangeEvent (Win32_PnPEntity diff, one event per kind per poll), Win32_VolumeChangeEvent (Win32_LogicalDisk; only "EventType = n" conditions). Diff by __RELPATH, modification by joined property values. Event and snapshot objects are detached IWbemClassObjects (struct dobj): wbemprox's own objects hold their table's critical section for their lifetime (grab_table), so keeping them on the poll thread deadlocked the caller's next query on that table (seen: table.cs wait timeout). Semisync enumerator (flags RETURN_IMMEDIATELY|FORWARD_ONLY required, as documented), async sinks in a per-services list, CancelAsyncCall by sink identity -> SetStatus(WBEM_E_CALL_CANCELLED). Event classes added to builtin tables (schema only). wbemdisp: ExecNotificationQueryAsync relay (message-only window on the calling thread; OnObjectReady per event, OnCompleted after Cancel), embedded objects returned to scripts as SWbemObject, SWbemSink EnumConnectionPoints/EnumConnections. wscript/cscript: WScript.Sleep pumps messages (Windows does; needed for sink events).
Limitations: polling, so a process shorter than ~200 ms can be missed; no event providers (registry events RegistryKeyChangeEvent etc., Win32_PowerManagementEvent, __TimerEvent) -> WBEM_E_INVALID_CLASS; GROUP/HAVING unsupported.
