8703 dlls/kbdsg (new), loader/wine.inf.in SgKeyboardLayoutFiles, configure -- apps10 (Siril 1.2.6 on qa4: Enter, Backspace, Ctrl+A did nothing in its command line; "Gdk-WARNING: Failed to translate keypress (keycode: 88) for group 0 (00000409) because we could not load the layout").
Cause: GTK 3.24 (gdk/win32/gdkkeys-win32.c update_keymap) maps keys from the layout DLL itself: GetKeyboardLayoutNameA -> HKLM\System\CurrentControlSet\Control\Keyboard Layouts\<KLID>\Layout File -> GetSystemDirectory\<file> -> LoadLibrary -> KbdLayerDescriptor -> KBDTABLES (pCharModifiers + pVkToWcharTable only). Wine has no layout DLLs and no Layout File values. Typed text still came through WM_CHAR, every other key was lost. GTK 4 does the same. Affects GIMP 3, Inkscape 1.x, darktable, Siril, ART, RawTherapee and every other GTK3/4 Windows build.
Fix: kbdsg.dll, KbdLayerDescriptor builds (and caches per HKL) the tables of GetKeyboardLayout(0) from ToUnicodeEx(flags 4) -- GTK activates each HKL before loading its DLL. Modifiers Shift/Ctrl/Alt, ModNumber 0,1,2,3,-,-,4(Ctrl+Alt),5; Ctrl levels empty (KBDUS), AltGr level only for characters of its own; CAPLOK for letters; dead keys as WCH_DEAD + 0xff row; VSC->VK 0..127. i386 build: KLP union with UINT64 (KBD_LONG_POINTERS), as GTK's WOW64 implementation reads. wine.inf: Layout File=KBDSG.DLL for the 72 language KLIDs of winex11's xkb_names plus the 12 layout-id variants (8212/8217), all four DefaultInstall sections.
Verified on qa4 (kbdsg.dll in lib + system32/syswow64, Layout File for 00000409 by hand): Siril's Backspace edits and Enter runs "load".
Gate kbdsg (test-kbdsg, Xvfb :313, US keymap): probe loads the DLL the way GTK does, 64- and 32-bit: Layout File, A a/A CAPLOK, 1 1/!, VK_BACK, VK_RETURN, Ctrl+C WCH_NONE, VSC 0x1e -> 'A'. 1084: all FAIL (no Layout File). Mutant SG_MUTANT_KBDSG_NO_TABLES. kbdlayout kbdhkl kbdklid kbddead kbdcues fastb-kbdload pass.
