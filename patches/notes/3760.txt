CORE review: combase (every cross-apartment COM call goes through ClientRpcChannelBuffer_SendReceive / rpc_execute_call). Docs: learn.microsoft.com CoGetCallerTID (the apartment of the caller's thread: STA its thread id, MTA 0, NA -1; S_TRUE/S_OK when the caller is in this process, S_FALSE when in another; no guarantee against tampering), IMessageFilter::RetryRejectedCall (-1: cancel, COM returns RPC_E_CALL_REJECTED; 0..99: retry at once; >=100: wait that many ms, then retry; called after HandleInComingCall answered SERVERCALL_RETRYLATER or SERVERCALL_REJECTED), CoRegisterSurrogate ("sets a global interface pointer to the ISurrogate interface"; S_OK); ground truth: ole32 marshal.c test_message_filter (a rejected call with no filter: RPC_E_CALL_REJECTED; with the same filter on both sides the retried call succeeds).
CoGetCallerTID: a side table of the calls this process makes to its own apartments (caller_push/pop in SendReceive, keyed by the causality id the call carries, topmost first, so a callback from the callee to the caller names the callee); rpc_execute_call looks the call's causality id up and keeps CALLER_INPROC + the calling thread (0 for an MTA caller) or CALLER_REMOTE in the thread data (unused words of struct tlsdata, so the layout is unchanged) for the duration of the invoke, restoring the old value (nested calls). CoGetCallerTID: in-process call -> S_OK + tid; call from another process -> S_FALSE + 0; no call being served -> S_OK + this apartment (thread id / 0); NULL -> E_INVALIDARG; no apartment -> CO_E_NOTINITIALIZED (GUESS: that code). Neutral apartments (-1) do not exist in combase here. No wire change: the caller of a call from another process is only known to be remote.
Retry: the callee's rpc_execute_call answers RPC_E_CALL_REJECTED (SERVERCALL_REJECTED) or RPC_E_SERVERCALL_RETRYLATER (SERVERCALL_RETRYLATER, was: ignored with a FIXME and the method ran) and restores the message so it can be sent again; for calls into an STA of this process (the posted-message path) SendReceive loops: the caller's apartment filter's RetryRejectedCall(callee thread id, ticks since the first try, SERVERCALL_REJECTED or _RETRYLATER) decides: -1 -> RPC_E_CALL_REJECTED, 0..99 -> retry now, >=100 -> wait that long taking messages (CoWaitForMultipleHandles) and retry; no filter (or an MTA caller) -> the rejection is returned (RETRYLATER as RPC_E_SERVERCALL_RETRYLATER, GUESS: the code for it). Not done: calls to another process are not retried (the transport may have taken the buffer; the rejection is reported) and a call into an MTA of this process goes through the RPC runtime and is not retried either.
CoRegisterSurrogate: NULL -> E_INVALIDARG (GUESS), otherwise the pointer is AddRef'd and kept in a global (a second registration replaces and releases the first). GUESS / not done: COM does not yet call LoadDllServer or FreeSurrogate on its own (Wine's dllhost drives them itself); CoRegisterSurrogateEx stays a stub.
