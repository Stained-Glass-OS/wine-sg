CORE review: behaviour change
 - ValidateProductID: ProductID is now set from PIDKEY only when the key fits the visible part of PIDTemplate (MaskedEdit syntax), as the ValidateProductID and ProductID topics describe; before, any PIDKEY was copied. The action still always succeeds. Hidden prefix + key + '-' + hidden suffix ('@' = random digit) when the template has <...>; the '<' side gets no dash (docs: only '>' becomes a dash). The "=" mask character (extra position + '-') is a GUESS, and the old mod-7 key check is not documented so it is not done.
 - MsiViewGetError: an error is reported once and the next one becomes current (Wine's own todo_wine tests in db.c/custom.c, run on Windows: second read -> MSIDBERROR_NOERROR); todo marks removed. The remote (custom action) size probe does not consume the error.
 - MsiViewModify VALIDATE_NEW with a _Validation table now also validates the columns (docs); without the table it behaves as before. REPLACE/VALIDATE/VALIDATE_FIELD/VALIDATE_DELETE and _Streams/_Storages DELETE/REPLACE/MERGE/REFRESH/INSERT_TEMPORARY did not work before (CALL_NOT_IMPLEMENTED).
 - _Streams MSIMODIFY_DELETE passed row-1 (off by one, always failed on the first row); a stream never committed no longer makes DELETE fail.
 - ACTION=ADVERTISE (MsiInstallProduct, msiexec /j) runs AdvtExecuteSequence/AdvtUISequence; it used to return ERROR_FUNCTION_NOT_CALLED. Publishing for ADVERTISED features is allowed only during that action (check_publish), so normal installs publish exactly as before.
 - open_package(): a product with no InstallProperties key (advertised only) falls back to its source list instead of failing ERROR_BAD_CONFIGURATION; if the source list is absent the old error stays.
 - MsiConfigureProductEx: SOURCE adds ADDSOURCE=ALL, ADVERTISED adds ADVERTISE=ALL (both were CALL_NOT_IMPLEMENTED); iInstallLevel 1..65535 for INSTALLSTATE_DEFAULT adds INSTALLLEVEL=n (docs); a level outside 0..65535 is ERROR_INVALID_PARAMETER (new, documented).
 - MsiApplyPatch: INSTALLTYPE_SINGLE_INSTANCE (product code) and INSTALLTYPE_NETWORK_IMAGE (ACTION=ADMIN PATCH=..., TARGETDIR left to the package: GUESS) work; both were CALL_NOT_IMPLEMENTED.
 - Internal UI (full UI level only): FILESINUSE/RMFILESINUSE show the package's own FilesInUse/MsiRMFilesInUse dialog when it has one (answer = EndDialog result), COMMONDATA [1]=2 enables/disables the Cancel button of the progress dialog, RESOLVESOURCE returns 0. Basic/reduced/none show nothing new. SpawnWaitDialog (full UI) shows its dialog while the row condition is false; ListView lines set the property (and the line holding the current value is selected).
 - MsiAdvertiseProduct[Ex]/MsiAdvertiseScript: the advertise script is OUR format (text file "SGADVSCRIPT 1" naming the package, product code, transforms, language, platform, options); it is written and read by msi.dll only. Applying a script runs ACTION=ADVERTISE on the named package, so the package must still exist (Windows scripts embed the data). phRegData != NULL (registry data under a caller key) stays CALL_NOT_IMPLEMENTED; the LocalSystem check is not enforced (a new failure path in installers).
 - MsiProvideAssembly: looks the assembly up in the keys MsiPublishAssemblies writes (global or per application), then MsiProvideComponent with the caller's mode; INSTALLMODE_NODETECTION_ANY only sees the last publisher. MsiProvideComponentFromDescriptor: decompose + MsiProvideComponent(INSTALLMODE_DEFAULT); *pcchArgs = descriptor length (offset of the arguments): no document or test covers it, GUESS.
