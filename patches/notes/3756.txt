CORE review: security (crypt32 system store opening is on the path of every HTTPS connection, code signing check and Root store lookup; the new code is only reached when a PhysicalStores key exists under the opened system store). Docs: learn.microsoft.com CertRegisterPhysicalStore, CertUnregisterPhysicalStore, CERT_PHYSICAL_STORE_INFO, CertEnumPhysicalStore (data: sdk-api markdown).
Registry layout (GUESS: the value names are the members of CERT_PHYSICAL_STORE_INFO; Microsoft does not document them): <system store key>\PhysicalStores\<name> with OpenStoreProvider (REG_SZ, or REG_DWORD for a numeric provider such as CERT_STORE_PROV_MEMORY), OpenEncodingType, OpenFlags, Flags, Priority (REG_DWORD), OpenParameters (REG_BINARY, the blob: a string store name for the System/SystemRegistry providers). Location -> hive as for system stores (CURRENT_USER in HKCU, LOCAL_MACHINE/enterprise/policy/services in HKLM or the service's key).
Behaviour: Register creates/updates the key (CERT_STORE_CREATE_NEW_FLAG on an existing store: ERROR_FILE_EXISTS; bad name (NULL, empty, backslash), NULL/short info, NULL provider, non-NULL reserved, CERT_SYSTEM_STORE_RELOCATE_FLAG, unknown location: E_INVALIDARG, GUESS for the codes). Unregister deletes the key (missing: ERROR_FILE_NOT_FOUND); CERT_STORE_DELETE_FLAG also deletes the store behind a System/SystemRegistry provider (CertUnregisterSystemStore). CertEnumPhysicalStore lists the registered ones after the built-in ones, with their info (provider pointer valid during the callback); a registered .Default replaces the built-in entry. Opening the system store (CRYPT_SysOpenStoreW) adds every registered physical store to the collection with CertAddStoreToCollection(flags & ADD_ENABLE only when the system store is not read-only, priority), skips CERT_PHYSICAL_STORE_OPEN_DISABLE_FLAG ones, skips the implicit registry store when .Default is registered, and stops after 4 nested openings (a physical store that points at its own system store).
Security: machine-wide locations (root HKEY_LOCAL_MACHINE) need Administrators membership in the calling token (CheckTokenMembership: a group present only to deny does not count) -> ERROR_ACCESS_DENIED; the wine registry did not refuse such a write from a restricted token (found while writing the gate), so the check is explicit and the HKLM registry ACL stays the second barrier on Windows-like setups. The user's own store needs nothing.
Not done / unverified: relocated stores; remote opening flags (REMOTE_OPEN_DISABLE, INSERT_COMPUTER_NAME) are stored and listed, not acted on; CERT_STORE_DELETE_FLAG for file providers; the physical stores of a user's view of the machine store (.LocalMachine entry) are the built-in ones only.
Gate fastb-physstore (registry layout, enum info, create-new, priority, add enable, read-only, open-disable, .Default replace/unregister, delete flag, loop guard, numeric provider, 14 argument errors, restricted-token children: standard user registers in HKCU but not HKLM, cannot unregister in HKLM); 24 mutants caught (CREATE_NEW_IGNORED DEFAULT_NOT_REPLACED PRIORITY_LOST UNREG_KEY_KEPT UNREG_DELETE_IGNORED UNREG_MISSING_OK REG_BACKSLASH_OK REG_RESERVED_OK REG_NO_PROVIDER_OK PARAMS_NOT_STORED RECURSION_UNBOUNDED REG_ADMIN_SKIPPED UNREG_ADMIN_SKIPPED ADMIN_FOR_ALL ENUM_NOT_LISTED HKCU_AS_HKLM NO_REGISTERED_PHYSICAL DISABLE_IGNORED ADD_ALWAYS ANY_USER; wrongly GRANTING: REG_ADMIN_SKIPPED UNREG_ADMIN_SKIPPED ANY_USER HKCU_AS_HKLM). Conformance 64/32 vs the series-applied base (3755): crypt32 (all suites), identical; wintrust, cryptnet, cryptui 0 failures.
