8412 winex11.drv/opengl.c: X11DRV_wglCreatePbufferARB makes XCreatePixmap(root, w, h, visual depth) + glXCreatePixmap instead of glXCreatePbuffer when GLX_MESA_query_renderer says GLX_RENDERER_ACCELERATED_MESA = 0 (cached) and the fbconfig has GLX_PIXMAP_BIT and a visual; release_gl_drawable frees the pixmap pair for such a pbuffer. Cause: Mesa drisw puts the front buffer of a GLXPbuffer with XShmPutImage -> BadMatch -> Xlib default handler exits (no Wine error handler match). Found by apps9: Sweet Home 3D 7.5 (Java 3D, 32-bit javaw) from SG Store on qa5 and on a host Xvfb exited before any window. With the fix (hand-deployed winex11.so on qa5) its window opens; its 3D view then reports "Error creating Canvas3D graphics context" on qa5 (AWT sets GDI format 8 on the canvas, Java 3D then format 24 -- a separate issue, not in this patch; on host Xvfb the 3D view comes up).
