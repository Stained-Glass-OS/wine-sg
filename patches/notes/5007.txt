5007 advapi32: gap-CORE items 60, 134-138 (DecryptFile/EncryptFile/FileEncryptionStatus A/W). The stubs claimed success. Now: a file system that cannot encrypt. Docs: https://learn.microsoft.com/en-us/windows/win32/api/winefs/nf-winefs-fileencryptionstatusw (FILE_SYSTEM_NOT_SUPPORT), https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-decryptfilew (needs exclusive access). Not a security-model change: nothing is encrypted and no keys are touched; EncryptFile now admits it cannot. Unverified: the exact error Windows gives for EncryptFile on a FAT/exFAT volume (ERROR_VOLUME_NOT_SUPPORT_EFS chosen from winerror.h, not tested on Windows); whether DecryptFile on a plain read-only file fails with ERROR_FILE_READ_ONLY on Windows (from the docs' "requires exclusive access"). Risk: an app that relied on EncryptFile "succeeding" now sees a failure - which is what it gets on a non-NTFS Windows volume. Gate test/advapi32-efs-gate.sh; mutants EFS_DECRYPT_NO_CHECKS, EFS_ENCRYPT_SUCCEEDS, EFS_STATUS_NO_FILE_CHECK.
