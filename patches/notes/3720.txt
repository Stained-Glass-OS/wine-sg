3720 comctl32 + user32 (gap-CLOUD). CORE review: Edit control (user32 v5 edit.c and comctl32 v6 edit.c), only reached when an app sends EM_FMTLINES.
 - EM_FMTLINES was a FIXME that did nothing. Now (docs: EM_FMTLINES) TRUE puts "\r\r\n" into the buffer at every wrapped line end, FALSE removes every soft break (also ones that came with the text); hard "\r\n" stay; WM_GETTEXT/WM_GETTEXTLENGTH/EM_GETHANDLE see the change, line count is unchanged, selection follows its text, undo buffer is emptied (GUESS: Windows' undo state is unknown), single-line controls are untouched, EN_ERRSPACE if the buffer cannot grow. Return value = wParam.
 - PGS_DRAGNDROP: the pager registers an IDropTarget (ole32 loaded on demand, program must have OleInitialize'd, as for the toolbar/tab drop targets). An item dragged over a scroll button scrolls at once, then after INITIAL_DELAY every REPEAT_DELAY until it leaves the button, DragLeave or Drop; effect is always DROPEFFECT_NONE (the contained window has its own target). Pager DnD only exercised through the IDropTarget (OleDropTargetInterface property) in the gate, not a real mouse drag.
 - Triaged no-ground-truth: ImageList_SetFilter, ImageList_SetFlags, TOOLBAR_Unkwn464 (undocumented, no tests).
Gate fastb-comctl (v5 and v6 Edit via an activation context; pager). Mutants caught: SG_MUTANT_NO_PAGER_DROP, SG_MUTANT_FMT_NOADD/NOREMOVE/NOSEL in both comctl32/edit.c and user32/edit.c.
