5223 gdi32: UpdateICMRegKeyA/W (gap-CORE 232, 233, PARTIAL).
Docs: learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-updateicmregkeya (obsolete; ICM_ADDPROFILE "installs the ICC profile in the system", ICM_DELETEPROFILE "uninstalls the ICC profile from the system, but does not delete the file", ICM_QUERYPROFILE "determines whether the profile is already installed", reserved must be zero).
Both returned TRUE without doing anything. Now, through mscms (loaded on demand): ICM_ADDPROFILE is InstallColorProfileW (copy into the colour directory), ICM_QUERYPROFILE tests for the profile's file name in the colour directory (ERROR_FILE_NOT_FOUND otherwise), ICM_DELETEPROFILE removes the installed copy (UninstallColorProfileW with the copy's path; the file the caller named is untouched). reserved != 0 or no file name: ERROR_INVALID_PARAMETER. The A version converts the file name (the CMID is ignored by these three commands).
NOT done: ICM_SETDEFAULTPROFILE ("first among equals"), ICM_REGISTERICMATCHER / ICM_UNREGISTERICMATCHER (CMM registration by a DWORD id), ICM_QUERYMATCH (a profile for a DEVMODE): they log a FIXME and fail with ERROR_NOT_SUPPORTED. The CMID/default/matcher registry layout is not documented and Wine has no CMM loading, so item 232/233 are PARTIAL and escalated.
Unverified: that the native "installed" test is the colour-directory copy (the docs do not say where the registry key lives); the error codes.
