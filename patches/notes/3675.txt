3675 tdh (tsv open: TdhLoadManifest, TdhLoadManifestFromBinary). New manifest.c (xmllite based parser) + tdh_private.h (public TRACE_EVENT_INFO / EVENT_PROPERTY_INFO layouts from the MS docs and mingw-w64 tdh.h; TDH_IN_TYPE / TDH_OUT_TYPE numbering from the MS enumeration pages). tdh now imports ole32 and xmllite.
TdhLoadManifest: ERROR_INVALID_PARAMETER (NULL / longer than MAX_PATH), ERROR_FILE_NOT_FOUND, ERROR_XML_PARSE_ERROR (not XML, or no <provider>), same path again replaces. TdhUnloadManifest: removes it, ERROR_NOT_FOUND if it was not loaded (GUESSED code). TdhGetEventInformation: ERROR_INVALID_PARAMETER, ERROR_NOT_FOUND (no manifest / event id+version unknown / WPP or classic event), ERROR_INSUFFICIENT_BUFFER with the needed size; properties: top-level first, struct members after them (StructStartIndex); count/length given as a property name set PropertyParamCount / PropertyParamLength with the index, numeric length sets PropertyParamFixedLength.
GUESSED: standard level texts (Information, Warning, Error, Critical, Verbose, Log Always) and standard opcode texts (Info, Start, Stop, DCStart ...); channels without a value are numbered from 16 in declaration order; default out types per in type (pointer types by pointer size); only the first <resources> culture's strings are used; an unresolvable $(string.x) message gives offset 0; TEMPLATE_EVENT_DATA flag always.
TdhLoadManifestFromBinary: documented errors only (INVALID_PARAMETER, FILE_NOT_FOUND, ERROR_RESOURCE_NOT_FOUND when there is no WEVT_TEMPLATE resource); the binary (CRIM) layout inside the resource is not documented by Microsoft, so a provider binary's manifest is not decoded: ESCALATE.md "tdh binary manifests". Not done either: TdhEnumerateManifestProviderEvents, TdhGetEventMapInformation, TdhFormatProperty, TdhGetProperty* (stubs without audit entries).
