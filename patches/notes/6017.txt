6017 wbemprox COM-WMI (ledger i0061, the SpawnDerivedClass part): user-defined WMI classes. IWbemClassObject::SpawnDerivedClass (flags must be 0) and IWbemServices::GetObject of no path give an uncommitted class: a detached dynamic table (TABLE_FLAG_SPAWNED) behind a view, the superclass's non-method properties copied; Put of __CLASS names it, Put of an unknown property adds it (type from the CIMTYPE or the VARIANT; arrays, objects and real32 are refused with WBEM_E_INVALID_PROPERTY_TYPE), the qualifier set of a property takes [key]; __CLASS is NULL until named, __GENUS class, __SUPERCLASS/__DERIVATION/__DYNASTY from the table's parent. IWbemServices::PutClass (CREATE_ONLY/UPDATE_ONLY honoured; a system class's name: WBEM_E_ACCESS_DENIED; no name: WBEM_E_INVALID_OBJECT), DeleteClass, PutInstance (key values required: WBEM_E_ILLEGAL_NULL; no key: WBEM_E_INVALID_OBJECT; CREATE_ONLY/UPDATE_ONLY), DeleteInstance by object path. Storage (new userclass.c): HKLM\Software\Wine\WBEM\<namespace>\Classes\<class> (Name, Superclass, Properties "type:name"), Instances\<key values> with REG_SZ/REG_QWORD values; find_table loads a class from there on a miss, and its fill reads the instances at every query, so other processes see current data. Writing HKLM needs an administrator, as the WMI repository's write access does (non-admins get WBEM_E_ACCESS_DENIED). Fixes on the way: qualifier sets released the table they found (it stayed grabbed, with its lock); set_value takes booleans; wbemcli.idl gets WBEM_CHANGE_FLAG_TYPE.
