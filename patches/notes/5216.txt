5216 win32u, wow64win: accessibility SPI_SET*/SPI_GET* pairs (gap-CORE 66).
Docs: learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-systemparametersinfow (SPI_SETSTICKYKEYS, SPI_SETFILTERKEYS, SPI_SETTOGGLEKEYS, SPI_SETMOUSEKEYS, SPI_SETACCESSTIMEOUT, SPI_SETSOUNDSENTRY, SPI_SETSERIALKEYS, SPI_SETHIGHCONTRAST: set the parameters of the accessibility feature from the structure; the GET counterparts retrieve them).
The eight SPI_SET actions logged "Unimplemented action" and failed with ERROR_INVALID_SPI_VALUE, and the GETs always returned the "feature not available" constants. They now go through the entry machinery SPI_SETSHOWSOUNDS already used: one value per DWORD field of the structure under HKCU\Control Panel\Accessibility (StickyKeys\Flags, Keyboard Response\Flags/DelayBeforeAcceptance/AutoRepeatDelay/AutoRepeatRate/BounceTime, ToggleKeys\Flags, MouseKeys\Flags/MaximumSpeed/TimeToMaximumSpeed/CtrlSpeed, TimeOut\Flags/TimeToWait, SoundSentry\..., SerialKeys\Flags/BaudRate/PortState/Active, HighContrast\Flags), held in memory and written when SPIF_UPDATEINIFILE is given (SPIF_SENDCHANGE broadcast as for every other action); the defaults are what the GETs returned before (0, MouseKeys max speed 360 / time 1000). A structure of the wrong cbSize or a NULL pointer fails with ERROR_INVALID_PARAMETER. wow64win converts the 32-bit SOUNDSENTRY / SERIALKEYS / HIGHCONTRAST structures for the SETs (the GETs already did).
Unverified: the registry value names are the ones commonly seen in Windows' HKCU\Control Panel\Accessibility but are not in the Microsoft docs; the string members (SOUNDSENTRY.lpszWindowsEffectDLL, SERIALKEYS.lpszActivePort/lpszPort, HIGHCONTRAST.lpszDefaultScheme) are not stored (they read back NULL); the features themselves (sticky keys, filter keys, mouse keys, ...) are not performed, only their settings kept; uiParam is not checked against the structure size.
