CORE review: ntdll heap (RtlCompactHeap is read-only here: it takes the heap lock and walks the sub heaps) and the C runtime of every program (_heapmin, _abnormal_termination are exported by msvcrt, msvcr70-120, ucrtbase, msvcrtd; the files are shared). Docs: learn.microsoft.com HeapCompact ("returns the size of the largest committed free block; 0 on failure, and 0 with GetLastError() == NO_ERROR if there is no space at all"), _heapmin ("0 if successful, -1 and errno ENOSYS if not supported"), AbnormalTermination (finally block ran because of an exception, a return/goto out of the try, as against falling off its end or __leave).
RtlCompactHeap: largest free block (size minus the block header) among the heap's sub heaps, 0 with ERROR_SUCCESS when none; an invalid (NULL or wrongly tagged) handle: 0 + ERROR_INVALID_HANDLE (GUESS: the code); blocks are merged with free neighbours and a free tail is decommitted as they are freed, so nothing is moved. Large blocks (their own mappings) are not free blocks.
_heapmin: clears the last error, calls HeapCompact on the heaps, fails only when it returns 0 AND set an error (so a heap with no free block is success). errno is set from the error as before (not for ERROR_CALL_NOT_IMPLEMENTED, which MS maps to ENOSYS: unchanged here).
_abnormal_termination: i386: true iff the top exception registration is msvcrt's nested handler of _local_unwind2/_local_unwind4 (what Windows' CRT does with its unwind handler), i.e. the finally block was called by a local unwind (exception unwinding, return or goto out of the try); other architectures: true iff the caller of the function that calls it (the finally funclet) is in ntdll (the unwinder, __C_specific_handler). On x64 / ARM64 compilers inline the check (the funclet's flag parameter), so this export matters for code that calls it through the CRT, e.g. mingw programs that call AbnormalTermination() of Wine's excpt.h. Unverified on a real compiled __try/__finally (no MSVC here); the gate drives the i386 side through _local_unwind2 with a hand-built frame and the x64 side through the exception dispatcher (a vectored handler is called from ntdll; a function it calls is not).
Gate fastb-abterm (64- and 32-bit probes): i386 local unwind (two finally levels abnormal, filter entry not run, trylevel, registration list restored, partial unwind, normal again), x64 dispatcher frames, HeapCompact sizes/merge/largest/used blocks/errors, _heapmin results and errno; 10 mutants caught (AT_LOCAL_UNWIND_NEVER/ALWAYS, AT_X64_NEVER/ALWAYS/WRONG_FRAME, HC_STUB/SMALLEST/USED_COUNTED/ERROR_LEFT/INVALID_OK caught; HM_ERROR_ON_ZERO is equivalent for any heap that has a free block, a full heap cannot be built). Conformance 64/32 vs the series-applied base (3758): msvcrt, ucrtbase, msvcr70-120, ntdll (all), kernel32 heap and virtual identical (one flaky ntdll exception.c failure in the base only).
