5115 rpcrt4: RpcServerUnregisterIfEx (gap-CORE item 588; a stub that did nothing and said success, so the interface stayed registered).
It removes the interface like RpcServerUnregisterIf does, always waiting for the calls on it to complete, and then deals with the context handles that calls of that interface made, in every client's association: if RundownContextHandles is non-zero their rundown routines are called, if zero they are only forgotten and their routines are never called. To know which handles belong to the interface, each server context handle now records the interface of the connection that made it (the connection's ActiveInterface). The shared part of RpcServerUnregisterIf became a static helper, which also no longer dereferences a NULL IfSpec when tracing.
Docs: learn.microsoft.com/en-us/windows/win32/api/rpcdce/nf-rpcdce-rpcserverunregisterifex ("waits for all calls on a given interface to complete before unregistering the context handles"; RundownContextHandles: "If non-zero, the rundown is called once all calls on the interface have completed. If set to zero, the RPC run time assumes the server has already destroyed its portion of the context handle and it will not call the rundown routines"; the interface must use strict_context_handle).
Unverified: a handle that a call still holds (reference count above one) is left alone; an IfSpec of NULL with a manager UUID removes only the first match as RpcServerUnregisterIf does; context handles of interfaces that are not strict are tagged by the connection's active interface, which is the interface of the call in Wine's one-interface-per-connection model. The existing behaviour that the rundown of a handle made under plain RpcServerUnregisterIf does not come soon after the client frees its binding (seen in the gate output) is not touched.
Gate test/rpcrt4-unregifex-gate.sh (probe test/rpcrt4-unregifex-probe.c with test/rpcrt4-unregifex.idl, 64+32 bit: a real client and server over ncalrpc in one process, stubs made by widl from the build tree: rundown on / off, plain RpcServerUnregisterIf calls none, a slow call in progress is waited for (900 ms), unknown interface).
