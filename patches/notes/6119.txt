6119 user32 win.c + wineboot shutdown.c (gaps5 leftover: NVDA 2026.2 "error in appModule 'explorer' ... cannot access submodule 'IAccessible' of module 'NVDAObjects' (most likely due to a circular import)").
Cause: NVDA core._initializeObjectCaches makes the desktop NVDAObject (GetDesktopWindow) and sets it as focus/foreground, which fetches the app module of the desktop window's process. On Windows that is csrss.exe (NVDA ships appModules/csrss.py for exactly this) and NVDA has no IAccessible import yet; here it was explorer.exe, so appModules.explorer imported NVDAObjects.IAccessible -> IAccessibleHandler, whose winEventToNVDAEvent annotation needs NVDAObjects.IAccessible half-initialised -> AttributeError; the explorer process kept the default app module for the session (no taskbar/desktop/Start support).
Fix: GetWindowThreadProcessId(desktop) from a process other than the desktop's own reports pid 4 (Wine ids start at 32, so never a live process; OpenProcess fails; not in a Toolhelp snapshot -> NVDA app name "" -> default module, as find_spec("appModules.") is None). The thread id stays the real desktop thread. The desktop's own process (explorer: vdesktop, systray, sysparams owner checks) still gets the truth; NtUserGetWindowThread (drivers: winex11, winewayland) is unchanged. wineboot (shutdown_close_windows / kill_processes skip the desktop process) now gets the pid from OpenThread(tid)+GetProcessIdOfThread.
Callers that need the desktop's real process: ole32 get_droptarget_local_handle (DuplicateHandle of the marshalled IDropTarget from the window's process -- explorer registers its drop target on the desktop window itself; with pid 4 a file dragged from File Explorer onto the desktop did nothing: test-drag failed 6 checks, passes with the fix) now uses the process of the window's thread; user32 clipboard.c's copy of it (X11 drops) uses NtUserGetWindowThread (unchanged truth). Mutant SG_MUTANT_DROPTARGET_BY_WINDOW_PID (ole32) caught by test-drag.
Audit (main's list): wine-sg tree -- every GetWindowThreadProcessId/NtUserGetWindowThread caller read; desktop-specific ones are user32 sysparams/PaintDesktop (owner check / nonzero: fine), winex11/winewayland/xrandr (NtUserGetWindowThread, unchanged), wineboot (fixed), ole32 + user32 drop targets (fixed), dwmapi thumbnails (dest==GetDesktopWindow compared by handle). sg-shell / sg-session / sg-compositor (fresh clones): 11 callers, all on EnumWindows top-levels, the foreground window or a given window (kiosk, flyout, bugreport, media, magnify, store, taskmgr, dictate, touchkbd, osk, pdf); none asks for the desktop window's process; sg-session and sg-compositor have none.
Mutant SG_MUTANT_DESKTOP_OWNER_EXPLORER (3 FAIL). Gate test-desktopowner: tid set, pid not explorer/self, not openable, not listed, 16-bit handle same, thread's process is explorer, own window still own. vdesk, sysshutdown, shutdown, shutdownexe, logoff, thumbbar, drag, uiaevents, uiabridge, oleaccstd, oleaccproxy, uiacachetree, usersessions pass (dwmthumb's 64-bit live-right fails with and without 6119: not this patch). Canary sweep (/var/tmp/canary/canary.sh, label gaps2-6119) on a make install of this tree: 27/27 gates rc=0, fail=0 (same as r602).
NVDA 2026.2 (installed, nvda.exe -m) in a scratch prefix: the explorer app module error is gone from nvda.log; remaining errors are audio/OneCore voices (no audio device in the scratch prefix).
