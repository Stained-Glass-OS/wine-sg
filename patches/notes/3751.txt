CORE review: security. secur32 LsaEnumerateLogonSessions / LsaGetLogonSessionData (DECISIONS-2 B SEC-LOGON, read only). The logon sessions are two: SYSTEM (LUID 0x3e7: user SYSTEM, domain NT AUTHORITY, S-1-5-18, LogonType Service, session 0) and the session of this process' token (its AuthenticationId, which is 0 here because tokens do not carry one yet: user, domain and SID from the token and the account database, LogonType Interactive, the token's session id); LogonServer is the computer name, the package is Negotiate, DNS domain and UPN are empty strings; any other LUID is STATUS_NO_SUCH_LOGON_SESSION; one block freed by LsaFreeReturnBuffer. Nothing is created or changed; no privilege is required (Windows asks for one for the enumeration - GUESS, not enforced). LogonTime is the boot time (GUESS). Wrong-GRANT mutants (session data for an unknown LUID, the SYSTEM SID for the user, a wrong type) caught: UNKNOWN_GRANTED SID_SYSTEM_FOR_USER SYSTEM_TYPE USER_TYPE ENUM_NO_SYSTEM ENUM_NO_CURRENT SESSION_FIXED NULL_UNCHECKED SERVER_EMPTY DOMAIN_EMPTY ENUM_NULL_CHECK. Gate fastb-logonsess. The other LSA functions (LsaLogonUser, credentials, session creation) stay escalated (SEC-LOGON beyond the approved subset).
