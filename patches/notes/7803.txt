7803 win32u: the focus never falls to a cloaked window (a window on another virtual desktop)

David 2026-11-15: "If you're on desktop 2, when you open up an application, it opens up on desktop 1 and switches
you over there." Start (a passing tool window) closed as it started the program; Wine's fallback activation
(activate_other_window) gave the foreground to the next window in Z order -- one on desktop 1, shell-cloaked but
still visible to Wine -- explorer's watch_foreground took that for a window brought forward and switched to
desktop 1, and the program, opening a moment later, was stamped with desktop 1. can_activate_window now passes
over cloaked windows (as Windows, whose virtual desktops cloak windows and never give them the focus by fallback).
A program that brings its window on another desktop forward on purpose (a single-instance app re-activating its
window) still switches, as on Windows.
Not the cause (checked): File Explorer (separate explorer.exe), a program started through start.exe, a framed
Linux program, a second Notepad -- all opened on desktop 2 and stayed.
Gate: test/vdopen-gate.sh (make test-vdopen): on desktop 2 with Notepad on desktop 1, a launcher tool window going
away leaves desktop 2 current; File Explorer, a start.exe-started program, a framed Linux stand-in and a second
Notepad open on desktop 2 and it stays. Mutant SG_MUTANT_ACTIVATE_CLOAKED caught.
