5096 netio.sys: WskControlSocket (gap-CORE item 1175).
WskSetOption -> setsockopt(level, code), WskGetOption -> getsockopt, WskIoctl -> WSAIoctl; with an IRP the result is the IRP's status/Information (an ioctl runs overlapped through the socket's pending-io slots, so SIO_ADDRESS_LIST_CHANGE does not block the caller), without an IRP the status returns directly and OutputSizeReturned gets the byte count. Winsock errors map through the existing table. Docs: learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wsk/nc-wsk-pfn_wsk_control_socket (no numeric values there).
Unverified/not done: the WSK-only options (SO_WSK_EVENT_CALLBACK, SO_WSK_SECURITY, SO_CONDITIONAL_ACCEPT handling) are not known to Winsock and fail with STATUS_INVALID_PARAMETER; they need the event-callback subsystem (see triage escalations of WskInspectComplete / WskControlClient). Our ws2_32 returns 1 byte for BOOL options where Windows returns 4 (the driver test accepts any non-zero length).
Gate test/ntoskrnl-netiotest-gate.sh (driver_netio.c test_wsk_control_socket, table of 10 requests, each without and with an IRP). Mutants NETIO_SETOPT, NETIO_GETOPT, NETIO_IOCTL fail it.
