5018 rpcrt4: gap-CORE item 26 (NdrClearOutParameters). Docs: https://learn.microsoft.com/en-us/windows/win32/api/rpcndr/nf-rpcndr-ndrclearoutparameters ("frees resources of the out parameter and clears its memory if the RPC call to the server fails"); COM memory rules (out pointers NULL on failure). Callers: Wine's stubless proxies (ndr_stubless.c STUBLESS_FREE, every non-basetype [out]/[in,out] parameter) and widl-generated proxies (RpcExcept with dwStubPhase != PROXY_SENDRECEIVE, every [out] parameter). Design decisions, unverified on Windows: (1) it acts only when dwStubPhase == PROXY_UNMARSHAL and the buffer has been read from (Buffer != BufferStart) - Wine's stubless proxy raises CO_E_OBJNOTCONNECTED from NdrProxyInitialize before zeroing the out parameters, so freeing then would free garbage, and after a failed SendReceive nothing was unmarshalled and [in,out] values are still the caller's; (2) for a top-level FC_RP only the pointee's contents are freed (the generic PointerFree would NdrFree the caller's own variable when FC_ALLOCED_ON_STACK is not set); (3) top-level FC_UP/FC_OP/FC_FP are ignored ([out] parameters are reference pointers). Risk: [in,out] parameters partly unmarshalled before a failure are now freed and zeroed (as the docs say) where they were left as is. calc_arg_size in ndr_stubless.c is no longer static. Suites rpcrt4 combase ole32 oleaut32 compared with base. Gate test/rpcrt4-clearout-gate.sh (hand-built stub messages and format strings); mutants CLEAROUT_ANY_PHASE, CLEAROUT_NO_ZERO, CLEAROUT_GENERIC_FREE.
