8217 winex11/wine.inf KBD-HKL follow-up to 8212 (coordinator: "do it like Windows"): the Layout Ids are Windows' own. Source: kbdlayout.info per-KLID metadata (public registry data; it shows Layout Id in decimal -- e.g. 00011009 "32", which a Windows NT 4.0 SP4 UPDATE.INF on ftp.zx.net.nz lists as "Layout Id"="0020", confirming hex in the registry). Values (registry hex): 00020409 0001, 00010409 0002, 00030409 001a (26), 00040409 001b (27), 00011009 0020 (32), 00010405 0005, 0001041b 0013 (19), 00010415 0007, 00010419 0008, 00020419 0033 (51), 0001041f 0014 (20), 0001041e 0021 (33). All confirmed; none guessed. 8212's 00010c0c "Canadian French (Legacy)" was wrong: Windows has 00000c0c = Canadian French (Legacy) (KBDFC) and 00001009 = Canadian French (KBDCA), both without Layout Id, i.e. language HKLs: xkb_names 0x0c0c -> ca(fr-legacy), 0x1009 -> ca (was us). [SgKeyboardLayoutsGone] DelReg removes the stray 00010c0c key from prefixes updated from 994-999.
Gate kbdklid extended: all 12 KLIDs -> Windows HKL + GetKeyboardLayoutName round trip, 00001009 types # on scan 0x29, wineboot -u removes 00010c0c. Without the change: 11 FAIL (fe0X HKLs, Canadian French); without the DelReg: 1 FAIL. kbdhkl, kbddead, kbdlayout pass.
