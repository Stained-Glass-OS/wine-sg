7805 server token.c: token_create_admin's default DACL on a shared prefix is sg_create_system_dacl (as token_create_for_uid's), not upstream's SY+Domain Users full.
Cause of David's Chrome no-sound (2026-11-15): the shell's desktop process on SYSTEM (elevated program's display; explorer desktop.c ProcessWineGrantAdminToken) did COM; combase NtCreateKey(\Registry\Machine\Software\Classes) on the SD-less key loaded from system.reg -> SYSTEM's stamping (registry.c) with that token's default DACL -> HKLM\Software\Classes O:DU D:(A;;GA;;;SY)(A;;GA;;;DU) (David's live regsd output, identical). USER_LIMITED (DU deny-only) then got ERROR_INVALID_HANDLE on HKCR and REGDB_E_READREGDB (David's comrestrict probe: hkcr_clsid=6 mmdevenum=0x80040150). Also closed: every user could write HKLM\Software\Classes. Not the cause: per-user HKCU\Software\Classes (combase falls back to the machine side; probe hkcu_classes=0), real per-user Chrome 157 as standard and split-admin user (audio service maps mmdevapi).
Recovery on an affected machine: SDs are not saved; the key loses the bad SD when the machine wineserver restarts (reboot) and this patch keeps it from coming back.
Gate: test/comrestrict-gate.sh (shared prefix, sgsystem + sgtest1): reproduces David's exact SD and errors with the mutant SG_MUTANT_ADMIN_TOKEN_UPSTREAM_DACL (2 FAIL); passes with the fix.
