6039 ntdll, kernelbase, cmd: the K-MOUNT "Left" item, JUNCTION GAP (6013's note: "junctions are Unix symlinks and read back as IO_REPARSE_TAG_SYMLINK, not MOUNT_POINT").
Change:
- sg_set_reparse_point stores a junction's absolute target with a trailing slash. A symbolic link's target has trailing slashes stripped.
- sg_link_reparse_tag reads the link: an absolute target ending in "/" is IO_REPARSE_TAG_MOUNT_POINT, anything else IO_REPARSE_TAG_SYMLINK. It is used by FileAttributeTagInformation and by directory entries (EaSize carries the tag of a reparse point; real mount points give MOUNT_POINT).
- sg_get_reparse_point returns the MOUNT_POINT layout for a junction: 16-byte header, no flags, subst "\??\C:\dir", print "C:\dir", each NUL-terminated.
- kernelbase FindNextFileW sets dwReserved0 from EaSize for reparse points. FindFirstFileExA and FindNextFileA copy dwReserved0/1; they did not.
- cmd mklink /J (create_junction) makes the directory and sets an IO_REPARSE_TAG_MOUNT_POINT reparse point to the target's full path. It printed "not supported" and failed.
Junctions made before this patch have no slash and still read as symbolic links.
Gate junction (test-junction): mklink /J; the junction's tag via FileAttributeTagInfo, FSCTL (tag, subst, print) and FindFirstFile dwReserved0; a mklink /D link keeps IO_REPARSE_TAG_SYMLINK in all three; dir through the junction; rmdir keeps the target.
Mutants caught: SG_MUTANT_JUNCTION_AS_SYMLINK (5 FAIL), SG_MUTANT_DIR_NO_TAG (2).

- kernel32 file, ntdll file and ntdll directory: 0 = 0.
