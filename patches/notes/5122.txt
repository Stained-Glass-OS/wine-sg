CoIsHandlerConnected (item 927) returned TRUE always with a FIXME. Docs
(combaseapi/nf-combaseapi-coishandlerconnected): TRUE if the object is not
remote or still connected to its remote handler; FALSE if remote and no longer
connected (the caller should release it). Now a proxy (recognised by its
IClientSecurity being the proxy manager's) is reported disconnected when
 - its apartment was torn down (the interface proxies lost their channels), or
 - the object it stands for lives in this process and its stub manager is gone
   (CoDisconnectObject on the server).
Everything else, including a server in another process, is reported connected:
telling would need a call over the wire (a ping through IRemUnknown) and the
docs do not say what Windows does. This is the part not covered.
