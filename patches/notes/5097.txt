5097 netio.sys: WskDisconnect (gap-CORE item 1062) and WskConnectEx (item 1064).
WskDisconnect: graceful = optional data sent first (a chained MDL is gathered into a WSABUF array), then shutdown(SD_SEND); the receive side stays open. A non-zero Flags value is the abortive disconnect (WSK_FLAG_ABORTIVE is the only documented flag, so no other bit is interpreted): Buffer must then be NULL (else STATUS_INVALID_PARAMETER), pending transfers are cancelled, SO_LINGER 0, shutdown(SD_BOTH).
WskConnectEx: Flags must be 0 (STATUS_INVALID_PARAMETER), Buffer > 65535 bytes gives STATUS_BUFFER_OVERFLOW, an unbound socket STATUS_INVALID_DEVICE_STATE; the data (chained MDLs copied into one block that lives until the connect completes) goes out with ConnectEx; address length is by family (so IPv6 works, unlike the older WskConnect which passes sizeof(SOCKADDR)).
Docs: learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wsk/nc-wsk-pfn_wsk_disconnect and nc-wsk-pfn_wsk_connect_ex.
Unverified: the numeric value of WSK_FLAG_ABORTIVE (no allowed source gives it; the test uses 1); the abortive disconnect ends the socket with a FIN rather than an RST on this stack (linger 0 only takes effect at close); status codes for a send after a disconnect are only checked to be failures; TCP_FASTOPEN is not set up.
