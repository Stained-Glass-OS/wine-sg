3216 msi.dll, CORE review of 3215: silent-install safety. Two defects found by the new gate checks (fastmsib1, section "silent install safety") and fixed here.
CORE review: behaviour change
 - MsiProcessMessage / internal UI: INSTALLMESSAGE_SHOWDIALOG now returns 0 without showing anything below the reduced UI level (NONE, BASIC, DEFAULT). Before, a SHOWDIALOG message (sent by the ShowDialog action or by a custom action through MsiProcessMessage) opened the authored dialog at BASIC; the UI sequence itself already did not run below REDUCED (needs_ui_sequence), the BASIC UI shows progress and errors only. This only REMOVES UI; the message still reaches the external UI handler first and the message log. The one case that changes outwardly: a package that shows an authored dialog from an execute-sequence action at BASIC no longer blocks on it (it returns 0 instead of the dialog's result).
 - COMMONDATA [1]=2 [2]=0 (hide/disable Cancel, 3215): the flag was applied before the next dialog's window existed, so the button stayed enabled; now it is applied when the window is created. Observable only with the full or reduced UI level. Positive control in the gate: the Cancel button of the following dialog is disabled.
Evidence, gate fastmsib1 (section test_silent), a package of our own with a file, an InstallUISequence (Main dialog -> SpawnWaitDialog "Wait" dialog, Done, Cancel) and FilesInUse / MsiRMFilesInUse dialogs; a watcher thread polls EnumWindows every 5 ms, the gate samples `xdotool search --onlyvisible` on its own Xvfb every 0.1 s and the probe names the phase in C:\phase.txt:
   - NONE and BASIC: ordinary install, uninstall, install with the target file held open without sharing (the replacement is queued in PendingFileRenameOperations, result 3010 ERROR_SUCCESS_REBOOT_REQUIRED, as documented for files that cannot be replaced), MsiProcessMessage FILESINUSE / RMFILESINUSE / COMMONDATA / RESOLVESOURCE / SHOWDIALOG, and a USER message at NONE: no window in the process and none on the X server, results 0, no SHOWDIALOG reaches the external UI handler (the UI sequence does not run).
   - FULL is the positive control: the same package shows Main, the watcher clicks Wait (SpawnWaitDialog shows the Wait dialog), Close, Done; FilesInUse shows the package's own dialog; the install completes with ERROR_SUCCESS (3 clicks).
   - ADVERTISE: a feature above the install level (Level 100) is advertised only because the ADVERTISE action defaults ADVERTISE=ALL, both through MsiAdvertiseScript and MsiAdvertiseProductEx; the old ADV mutant (3215) was unobservable, it is now caught.
Mutants (SG_MUTANT_MSIB1_*, driver work/muts-msib1b.sh, results work/muts-msib1b.out), all caught: UIBASIC (SHOWDIALOG shows at BASIC), UIFILES (FILESINUSE dialog at BASIC), UINONE (no NONE guard: a message box at NONE), UISEQ (UI sequence runs below REDUCED), CANCEL (3215 defect), SPAWN (SpawnWaitDialog fires on the wrong condition), INUSE (file-in-use result), ADV (ADVERTISE=ALL default).
msi conformance (tests of the dev tree, with the marks the series removed): db automation msi package install action source patch suminfo format record, 64 and 32 bit, 0 failures.
UNVERIFIED: what native Windows returns from MsiProcessMessage(FILESINUSE) without UI (we return 0); that BASIC never shows authored dialogs on Windows is from the UI level documentation (INSTALLUILEVEL_BASIC: simple progress and error handling), not from a test.
