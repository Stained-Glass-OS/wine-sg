5110 ole32: OleConvertIStorageToOLESTREAMEx (gap-CORE item 506; it logged "stub" and returned E_NOTIMPL).
OleConvertIStorageToOLESTREAM's body is now a helper that can take the presentation data from the caller: with a clipboard format the second object of the OLE 1 stream (otherwise the presentation of the storage's OlePres000 stream, or nothing) is a StandardPresentationObject of [MS-OLEDS] section 2.2.2 (learn.microsoft.com/en-us/openspecs/windows_protocols/ms-oleds): FormatID 5, class name "METAFILEPICT" / "DIB" / "BITMAP" as a length-prefixed ANSI string, width, height multiplied by -1, the size of the data, for a metafile 8 reserved bytes (counted in the size) in front, then the bytes. The bytes come from the STGMEDIUM, TYMED_HGLOBAL or TYMED_ISTREAM only (docs: learn.microsoft.com/en-us/windows/win32/api/ole2/nf-ole2-oleconvertistoragetoolestreamex; the medium is not released), dwSize of them. A NULL format ignores width/height/size/medium. E_INVALIDARG for a NULL storage or stream, a format with no medium, another tymed, an HGLOBAL smaller than dwSize, a short stream.
Unverified: other clipboard formats (GenericPresentationObject, 2.2.3: CF_ENHMETAFILE, registered formats) answer E_INVALIDARG with a FIXME (the docs list only E_INVALIDARG; the spec's generic layouts are not written by the existing OLESTREAM writer); the 8 reserved metafile bytes carry mm=8 and the extents as the storage-based path did; a metafile medium is taken as the metafile bytes themselves, not a METAFILEPICT structure.
