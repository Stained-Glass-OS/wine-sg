6029 combase (found by 6030's gate: a package's COM server registered for the user was not created): open_key_for_clsid and open_appidkey_from_clsid opened \Registry\Machine\Software\Classes only, so a class or AppID registered under HKCU\Software\Classes -- per-user installs (Chrome/Edge/Teams updaters, Zoom, Slack, toast activators), packages' COM servers -- was REGDB_E_CLASSNOTREG (0423-era code in rpc.c handled only a per-user LocalServer32). As in Windows' merged HKEY_CLASSES_ROOT, the user's CLSID\{x} (and the requested subkey, InprocServer32/LocalServer32/...) or AppID\{x} now comes first, the machine's otherwise; a key of the user's without the requested subkey falls back to the machine's. A process whose token is elevated (TokenElevation) uses the machine's alone -- Windows' rule that keeps a user's registrations from code running with full rights.
Docs: learn.microsoft.com "Merged View of HKEY_CLASSES_ROOT", "HKEY_CLASSES_ROOT Key" (per-user COM registration; elevated processes).
Gate comuser (test-comuser): an unregistered class REGDB_E_CLASSNOTREG; registered under HKCU it is created; the user's registration wins over the machine's (HKLM pointing at a missing DLL); a user's key without InprocServer32 leaves the machine's server; once the user's is deleted the machine's (missing DLL) is used again. Mutant caught: SG_MUTANT_COM_NO_USER_CLASSES (2). Not verified in the gate: the elevated-process rule (a plain prefix's token is not elevated).
