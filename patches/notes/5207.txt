5207 user32: DDEML conversation lists (gap-CORE 634 DdeConnectList, 635 DdeQueryNextServer, 636 DdeDisconnectList).
Docs: learn.microsoft.com/en-us/windows/win32/api/ddeml/nf-ddeml-ddeconnectlist, ddequerynextserver, ddedisconnectlist.
DdeConnectList used to return the constant 1 (not a list). Now: it asks every top-level window to start a conversation through a client window of its own (WM_DDE_INITIATE with the given service/topic atoms, 0 = wildcard, SMTO_ABORTIFHUNG 2 s), keeps each server that answers as a client conversation, and returns a list handle (heap object, magic checked); an existing list passed in keeps its conversations that are still alive (same HCONV values), adds new servers (same service+topic pair = same conversation) and is freed; no server gives 0 with DMLERR_NO_CONV_ESTABLISHED, a bad list/instance 0 with DMLERR_INVALIDPARAMETER (instance known). DdeQueryNextServer walks the list skipping dead conversations; DdeDisconnectList disconnects them and frees the list; DdeUninitialize frees the instance's lists.
Unverified: the order of the conversations (window enumeration order), what Windows returns from DdeQueryNextServer for a handle not in the list (0 here), that every server window is asked (as the DdeConnect broadcast does), and servers that answer several wildcard pairs from one window give one conversation per window.
Gate test/user32-ddelist-gate.sh (four in-process DDEML servers with wildcard support, 35 checks per arch, 64/32); mutants DDELIST_STUB, DDELIST_ONE, DDELIST_NOREFRESH shown failing it. user32 dde conformance tests are part of the full suite run.
