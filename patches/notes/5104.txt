5104 ntdll: NtPowerInformation(SystemPowerCapabilities) follows the machine (gap-CORE item 55, a "semi-stub" FIXME logged on every call).
Earlier patches already made the battery, sleep states, thermal zone and throttling real; what stayed an XP desktop's canned answer is now read from the host too: the lid (the "Lid Switch" input device; the old /proc/acpi/button/lid files no longer exist on current kernels, so a laptop's lid was never found), the power and sleep buttons (the "Power Button" / "Sleep Button" input devices; a host that does not list its input devices keeps the desktop answer), S3 (only "deep" in /sys/power/mem_sleep is a real suspend to RAM; "s2idle" is not) and DiskSpinDown (a rotating, non-removable block device). The FIXME becomes a TRACE.
Docs: learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-system_power_capabilities (field meanings); the Linux files are from the kernel's Documentation (sysfs power, input).
Unverified: RtcWake / AcOnLineWake / SoftLidWake / MinDeviceWakeState keep their old values (no ground truth for mapping them from the host); S1 still counts the kernel's "freeze" as well as "standby"; Modern Standby (AoAc) is not reported (the struct here has no such field).
