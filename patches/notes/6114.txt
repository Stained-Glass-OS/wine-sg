6114 server file.c sd_to_mode (main's high-priority field item, qa4 wine 633: CCleaner installs through the Store, bob cannot run it, uninstall "could not be started (error 5)"). qa4: Program Files\Piriform and CCleaner 7 were sgsystem:sgsystem, user::rwx user:sgsystem:rwx group::r-x mask::rwx other::---, made by the elevated installer with an explicit DACL (SYSTEM full, Administrators full, Users read+execute). sd_to_mode maps a Users / Authenticated Users / Interactive ACE to the group's bits only (sg_is_users_sid); the group becomes the users' group (sgwine, sg_users_group) only when the users get write. With read/execute only, the folder kept its maker's group (Program Files is not setgid on a system: sgsystem's own), and other::--- shut every user out of the folder: no CCleaner.exe start, the uninstaller (Common Files\Piriform\Icarus\piriform-ccl\icarus.exe) error 5.
Fix: an ACCESS_ALLOWED ACE for the users also sets the others' read and execute bits (DENIED for the users clears them); write stays the group's (users' group via sg_users_group), so nothing becomes world-writable. Users' read on Windows is every local account's; the Unix others are those accounts here. Mutant SG_MUTANT_USERS_READ_GROUP_ONLY.
