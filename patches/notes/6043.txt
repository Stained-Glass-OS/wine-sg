6043 appxdeploymentclient: sign-in cleanup of a user's stale package registrations. Main's question 3 after 6042: on Windows AppReadiness drops a user's registration whose package was removed for all users or whose content is gone. Main reviewed the draft before commit.
How it works:
- SYSTEM's removal of a machine record adds the full name to HKLM\Software\Wine\AppModel\RemovedPackages (64-bit view). SYSTEM's write_record of that full name clears it.
- for_each_record calls cleanup_stale_user_records first, once per process (InitOnce) and never as SYSTEM. It drops the user's HKCU records whose full name is in RemovedPackages, or whose InstallLocation is missing. A package with external content is dropped only if that external content is missing too (main: Dropbox's per-user WindowsApps folder may be gone while its external content stays).
- Development-mode and staged registrations stay.
- Dropping removes the record's aliases (only those pointing into its install location), Start menu shortcuts and HKCU COM classes, then the record. Package files are never deleted. Stale names are collected first and dropped after the enumeration.
- query_record counts a version as available when its folder or its external content exists.
Gate sysappx (test-sysappx), new checks:
- a user record whose files are gone is dropped;
- a sparse user record with its folder gone but its external content there is kept;
- after SYSTEM removes the machine package, the user's own registration of it and its Start menu entry are dropped at the user's next query;
- the one-version check uses an older registration with an existing folder (otherwise cleanup would remove it first).
