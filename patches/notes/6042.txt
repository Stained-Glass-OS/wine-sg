6042 appxdeploymentclient + include/windows.applicationmodel.idl. This is the Dropbox start crash on 501 (main: qa5/qa4 AV, rax=E_NOINTERFACE, rcx=0).
What the instrumented run on qa5 showed: Dropbox walks FindPackagesByUserSecurityIdPackageFamilyName and reads Id.FullName and Version. It then reads Package.Status's flags five times and QIs the PackageStatus for IPackageStatus2 (IsPartiallyStaged). The status object answered only IPackageStatus, so Dropbox called through the NULL it got.
Why it ran on 488: Dropbox's sparse package is added with IPackageManager9.AddPackageByUriAsync (6028, 10.0-492), so before 6028 no record existed and the walk found nothing.
Fixes:
- IPackageStatus2 (uuid f428fa93-7c56-4862-acfa-abaedcc0694d, from the MIT windows crate) is declared in the IDL. The status object answers it (IsPartiallyStaged FALSE: a package found as registered has all its content), lists it in GetIids, and gives a FIXME for other IIDs.
- (main's question 2) One version of a main package's family per query, as Windows registers one per user. The version whose InstallLocation exists wins, then the newest. Frameworks and resource packages keep their side-by-side versions. Before, a user registration plus a machine one (6036), or a stale update record whose files were removed, showed twice.
Gates:
- sparse: new `sparse-probe status FAMILY` (the Dropbox walk: Id, status flags, IPackageStatus2) on the sparse package.
- sysappx: the same walk as the standard user over the machine's package. Then a stale newer HKCU record of the family (2.0.0.0, InstallLocation gone) is added: the family shows once, as the available 1.0.0.0.
Mutants caught: SG_MUTANT_AX_NO_STATUS2 (2 FAIL), SG_MUTANT_AX_TWO_VERSIONS (2).
Regression: gates sparse, sysappx, pkgverb, msix2, pm3 and fastappmodel pass. No Wine conformance tests cover appxdeploymentclient.
Not done (main's question 3), and why: when SYSTEM removes a package, other users' stale registrations of the family stay in their HKCU, because their hives are not loaded in SYSTEM's process. With this patch such a record is hidden when another version is available. Otherwise it shows with Status.NotAvailable, as Windows reports a registration whose content is gone.
