5226 user32 DrawAnimatedRects, win32u SPI_GETANIMATION/SPI_SETANIMATION.
Docs: learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-drawanimatedrects ("Animates the caption of a window to indicate the opening of an icon or the minimizing or maximizing of a window"; idAni "must be IDANI_CAPTION"; the animation is clipped to the parent of hwnd; lprcFrom/lprcTo relative to the clipping window; nonzero on success) and nf-winuser-systemparametersinfoa (SPI_GETANIMATION / SPI_SETANIMATION, ANIMATIONINFO.iMinAnimate).
DrawAnimatedRects was a FIXME returning TRUE. It now moves a dotted XOR frame from lprcFrom to lprcTo in 200 ms (frames every 15 ms, Sleep between, erased by a second XOR before returning), on a cached DC of the parent of hwnd (the desktop for a top-level window or NULL hwnd). No timer or thread is left behind; the gate samples process CPU and WM_TIMER for 1.5 s afterwards.
It draws nothing (and returns TRUE) when SPI_GETANIMATION iMinAnimate is 0 or SPI_GETCLIENTAREAANIMATION ("Show animations" in our Settings) is off. NULL rectangle: FALSE, ERROR_INVALID_PARAMETER; destroyed hwnd: FALSE, ERROR_INVALID_WINDOW_HANDLE; idAni other than IDANI_CAPTION: TRUE, nothing drawn.
win32u: SPI_GETANIMATION used to answer iMinAnimate 0 always and SPI_SETANIMATION was a warning that failed. They now use the Windows value HKCU\Control Panel\Desktop\WindowMetrics "MinAnimate" ("0"/"1"). The default stays 0, so no behaviour changes for any program until the user or Settings sets it; sg-shell's Settings does not write MinAnimate yet (integrator: decide whether the default should become 1 like Windows, and whether Effects > minimize should set it).
Unverified: the exact duration, step and look of the Windows frame (the docs give none); whether Windows draws for the IDANI_OPEN/IDANI_CLOSE values (undocumented here, answered TRUE without drawing); the cross-process cache of MinAnimate (Wine caches SPI values per process, like every other entry).
Existing patches: none of 0521/0751/0752 (explorer/winex11 minimize and task view animations) call DrawAnimatedRects or read MinAnimate; their behaviour is unchanged.
