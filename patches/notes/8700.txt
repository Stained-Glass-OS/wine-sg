8700 dlls/sapi/token.c -- apps10 (Thorium Reader's read aloud stopped at the first sentence on qa4, wine 10.0-1100).
Cause: SpObjectTokenCategory::SetId(SPCAT_VOICES) opened HKLM\SOFTWARE\Microsoft\Speech\Voices with KEY_ALL_ACCESS. Since 3764 machine keys carry Windows' descriptor (Users read), so a standard user and an unelevated administrator got ACCESS_DENIED -> SPERR_INVALID_REGISTRY_KEY; SpVoice had no voice and Speak returned the same error. Every SAPI 5 TTS client in a normal session was mute (probe speak.exe: setid 80045040).
Fix: open_key_rw_or_ro(): KEY_ALL_ACCESS first, on ERROR_ACCESS_DENIED KEY_READ. Used by category SetId and GetDataKey, EnumTokens' Tokens key, token SetId, data key OpenKey/CreateKey. HKCU writes (default token id, volatile enum cache) unchanged. Writing to a read-only key still fails (E_ACCESSDENIED), as on Windows.
Verified on qa4 as alice: speak.exe enumerates "Stained Glass Voice (eSpeak NG)" and Speak returns S_OK after 5 s of speech.
Gate sapiro (test-sapiro): the probe builds a category under HKCU with a read-only DACL (D:P(A;;KR;;;WD)), so it does not depend on who runs it: SetId, EnumTokens, token name, Attributes\Language, token SetId, default token; SetStringValue refused. 1084/1100: FAIL. Mutant SG_MUTANT_SAPI_NO_READONLY_KEYS.
