3627 cldapi (decision 1). Whole user-mode surface of cldapi.spec in dlls/cldapi/main.c from Microsoft's cfapi documentation (cfapi.h is not available: structure layouts CF_SYNC_REGISTRATION/POLICIES/CALLBACK_INFO/PARAMETERS/OPERATION_INFO/PARAMETERS/PLACEHOLDER_CREATE_INFO written from the docs, x64 layout with the 8-byte-aligned unions: unverified against Windows binaries).
State: sync roots in HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\SyncRootManager\<provider>!<hash of path> (Path, ProviderName/Version/Id, SyncRootIdentity, FileIdentity, Policies, Flags; unverified key layout). Placeholder metadata (flags, identity up to 4 KB, pin, in-sync, up to 16 on-disk ranges) in %LOCALAPPDATA%\Microsoft\CloudFiles\<volume serial>-<file index>.sgcf; alternate data streams are refused by this Wine, so none are used. A placeholder is a sparse file of its logical size. Pin states also set FILE_ATTRIBUTE_PINNED/UNPINNED.
Errors: ERROR_NOT_A_CLOUD_FILE (376) for plain files, ERROR_CLOUD_FILE_ALREADY_CONNECTED (378) for a second register/connect, ERROR_CLOUD_FILE_INVALID_REQUEST (380) for a misaligned TRANSFER_DATA or an unknown transfer key, ERROR_CLOUD_FILE_NOT_UNDER_SYNC_ROOT (390), ERROR_NOT_A_CLOUD_SYNC_ROOT (405) for connect/unregister of a path that is not a sync root, ERROR_CLOUD_FILE_NOT_IN_SYNC (377) for reverting a file not fully on disk, ERROR_CLOUD_FILE_PROVIDER_NOT_RUNNING (362) when nobody is connected, ERROR_CLOUD_FILE_REQUEST_TIMEOUT (426) after 30 s without the data.
Hydration: CfHydratePlaceholder calls the connection's FETCH_DATA callback synchronously with the required range, then waits for CfExecute to cover it; a TRANSFER_DATA with a failing CompletionStatus fails the request with that status. NOT available: hydration when a program opens or reads a placeholder (that is a filter driver), dehydration requests, delete/rename notifications, VALIDATE_DATA. CfGetPlaceholderStateFromAttributeTag decodes the cloud reparse tags (0x9000001a with flag bits) from the attributes only.
