5214 win32u: NtGdiDdDDIEscape / D3DKMTEscape (gap-CORE 669; recheck of drafter 7).
Docs: windows-driver-docs-ddi d3dkmthk/nf-d3dkmthk-d3dkmtescape (STATUS_SUCCESS, STATUS_DEVICE_REMOVED, STATUS_INVALID_PARAMETER "parameters were validated and determined to be incorrect", STATUS_NO_MEMORY "insufficient memory", ...; it exchanges data with the kernel-mode display miniport driver).
It returned STATUS_NO_MEMORY for everything. Now: STATUS_INVALID_PARAMETER for a NULL structure, an adapter handle that is zero or not an open adapter (D3DKMTOpenAdapterFrom*; also after D3DKMTCloseAdapter), an escape type past D3DKMT_ESCAPE_DIAGNOSTICS, or a private data size without a pointer; any valid request is STATUS_NOT_SUPPORTED because Wine has no kernel-mode driver to exchange the data with.
Unverified: STATUS_NOT_SUPPORTED as the answer for a valid request (the docs allow "other NTSTATUS values"; what a real driver answers for data it does not know is its own choice); device handles (hDevice) are not supported at all (no D3DKMTCreateDevice), so an hAdapter of 0 is invalid; STATUS_NO_MEMORY, DEVICE_REMOVED and the privileged/illegal instruction codes can not happen here.
