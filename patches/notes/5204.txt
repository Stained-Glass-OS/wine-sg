5204 win32u: NtGdiRemoveFontMemResourceEx (gap-CORE 718).
Docs: learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-removefontmemresourceex ("removes the fonts added from a font resource in memory"); gdi32 tests/font.c test_AddFontMemResource / test_GetGlyphIndices call it and expect TRUE for the handle AddFontMemResourceEx returned.
AddFontMemResourceEx returned the font image's address XOR a constant; in a WoW64 process the 32-bit handle lost the upper half, so it could not be turned back into the image. The handle is now a number from a list of added resources (non-zero, first is 1). RemoveFontMemResourceEx finds the resource, drops the faces made from its image from the font families, and frees realized fonts nobody uses (the font cache would otherwise still find them by name); an unknown, zero or already-removed handle gives FALSE with ERROR_INVALID_PARAMETER (the docs only say FALSE; the error code is a guess). Fonts still selected into a DC keep working and the image copy is never freed (they read from it), as before - a leak of one font file copy per AddFontMemResourceEx.
Unverified: Windows' value for the handle (opaque to callers), error code on a bad handle, behaviour when the same bytes are added twice (two resources, two removals).
Gate test/win32u-memfont-gate.sh (builds a TrueType font in memory with test/sgfont.h, adds two, removes them in turn; 64 and 32 bit); mutant MEMFONT_STUB (the old always-TRUE) shown failing it.
