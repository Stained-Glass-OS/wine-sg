6075 wsdapi (N-WEBSERVICES/WS-Discovery). WSDCreateDiscoveryProvider was an E_NOTIMPL stub: programs that look for WS-Discovery devices (printers, scanners, cameras, media servers) found none.
- provider.c (new): IWSDiscoveryProvider + IWSDiscoveredService. SearchByType: multicast Probe (239.255.255.250 / FF02::C, port 3702) from a socket on an ephemeral port, sent twice, replies read for MATCH_TIMEOUT (10 s, from the SearchFailed docs); only ProbeMatches whose RelatesTo is our MessageID; endpoints deduplicated per search. SearchById: Resolve, ends at the first ResolveMatch. SearchByAddress: directed Probe POSTed with winhttp (21 s timeouts). SearchComplete if any Add, else SearchFailed(S_FALSE) (documented); a failed HTTP transmission gives its error.
- Errors per the docs: E_POINTER, E_ABORT (not attached / attached twice / Detach unattached), E_INVALIDARG (lengths over WSD_MAX_TEXT_LENGTH, no id, no http(s) URL, MatchBy without scopes, an incomplete type name). SetAddressFamily after Attach: STG_E_INVALIDFUNCTION (as the publisher's; not checked against Windows).
- LAN rule (main): Hello/Bye listener (UDP 3702, SO_REUSEADDR, group joined per adapter) exists only between Attach and Detach, or until the provider is released; no firewall or system config. Outgoing probes only otherwise.
- soap.c: read_message takes impl==NULL; reads ProbeMatches/ResolveMatches/Hello/Bye into struct wsd_match lists (EPR address, types with namespaces, scopes, XAddrs, metadata version) and RelatesTo; build_search_message. AppSequence is optional in written headers.
- Upstream bugs fixed: build_types_list_from_string never kept the list tail (2+ types crashed, also in the publisher's Probe reader); build_types_list/build_uri_list compared byte counts with character pointers (heap overflow on long lists); the publisher's listener bound the adapter's unicast address and so never received multicast Probes on Linux (now the wildcard address, group still joined per adapter); a Probe without Types (optional per WS-Discovery) was dropped before the publisher's handler.
- Not done: GetExtendedDiscoXML returns no extension elements; GetLocalInterfaceGUID is zero; WSDCreateDiscoveryProvider2 (config params) stays a stub.
Gate: test-wsdprovider (unshare -rnm, lo multicast; test/wsdprovider-device.py target service; Wine's own publisher; ss proves no listener after Detach/Release). Mutants SG_MUTANT_WSD_ANY_RELATES, SG_MUTANT_WSD_NO_FAILED, SG_MUTANT_WSD_KEEP_LISTENING, SG_MUTANT_WSD_BIND_UNICAST caught. Wine's wsdapi tests pass.
