5117 rpcrt4: NdrConformantStructMemorySize (gap-CORE item 571, FIXME stub returning 0 without touching the buffer) and NdrContextHandleSize (item 582, FIXME stub doing nothing).
NdrConformantStructMemorySize: the memory a conformant struct (FC_CSTRUCT / FC_CPSTRUCT) takes once unmarshalled from the buffer: the conformance count is read from the buffer, then the fixed part and count * element size are added to MemorySize and skipped in the buffer, and for FC_CPSTRUCT the embedded pointers' memory is added; it follows NdrConformantStructUnmarshall step for step (the same code shape as the existing NdrConformantVaryingStructMemorySize / NdrSimpleStructMemorySize). NdrContextHandleSize: the size of a context handle on the wire = what the context handle's buffer-size routine adds (4-byte alignment, then the 20 bytes of a wire context handle); docs: learn.microsoft.com/en-us/windows/win32/api/rpcndr/nf-rpcndr-ndrcontexthandlesize ("returns the size of the supplied RPC context handle ... The BufferLength member contains the size").
Unverified: neither function has a Windows run in Wine's tests; the struct function is written against the unmarshaller's behaviour, and the gate checks it against it (same buffer position afterwards) and against the in-memory size.
