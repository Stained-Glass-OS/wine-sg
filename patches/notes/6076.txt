6076 ntdll + wineserver (K-LPC). The legacy LPC port calls were stubs (STATUS_NOT_IMPLEMENTED). Sources: Microsoft's NT Debugging blog "LPC Part 1: architecture" (port kinds, connection sequence, the 304-byte message buffer, NtListenPort drops all but connection requests), Wine's dlls/ntdll/tests/port.c (message types, WoW64 64-bit layout, datagram/request/reply/client-died flow). Clean room: no disassembly, no ReactOS.
- server/port.c (new object type "Port"): connection port (named, create_named_object, default object security like events), client communication port, server communication port. Server-side messages (connection requests, requests and datagrams of every client, LPC_PORT_CLOSED, LPC_CLIENT_DIED) are queued on the connection port and received through any server port; client messages on the client port. Received requests/connection requests are kept (awaiting) until replied/accepted, only by the receiving process. Replies go to the sending port for the waiting thread; signaled() is per waiting thread (reply there / other side gone, else something to receive; a connecting client once answered).
- Requests: create_port, connect_port, get_port_connect_result, accept_port_connect, complete_port_connect, send_port_message, receive_port_message, register_terminate_port (protocol 876: full rebuild of all unix modules). kill_thread -> port_thread_terminated (LPC_CLIENT_DIED). Last handle closed -> LPC_PORT_CLOSED to the server / STATUS_PORT_DISCONNECTED to a waiting client; a closed connection port is unlinked and refuses pending connections.
- ntdll: NtCreatePort/NtCreateWaitablePort (MaxMessageLength includes the 40-byte header; data capped at 304), NtConnectPort/NtSecureConnectPort (SID compared with the server process's user: STATUS_SERVER_SID_MISMATCH), NtListenPort, NtAcceptConnectPort (context = id parameter), NtCompleteConnectPort, NtRequestPort, NtRequestWaitReplyPort, NtReplyPort, NtReplyWaitReceivePort(Ex, timeout), NtRegisterThreadTerminatePort. New syscalls NtCreateWaitablePort/NtReplyPort/NtReplyWaitReceivePortEx/NtRequestPort (renumbered table) + wow64 thunks (messages passed as-is: 64-bit layout) + arm64ec declarations.
- Picks not checked against Windows: connection info over the port's maximum and data over the maximum -> STATUS_PORT_MESSAGE_TOO_LONG; accept/reply of an unknown id -> STATUS_REPLY_MESSAGE_MISMATCH; MaxConnectionInfoLength over 260 -> STATUS_INVALID_PARAMETER.
- Not done: shared sections (LPC_SECTION_WRITE with a section -> STATUS_NOT_SUPPORTED; read views report size 0), NtImpersonateClientOfPort, NtRead/WriteRequestData, NtReplyWaitReplyPort, NtQueryInformationPort, ALPC (NtAlpc*).
- Security: a port is a named object with the default object security of this system (same as events/sections); NtSecureConnectPort lets a client require the server's user. Nothing new is exposed beyond what named objects already are.
Gate: test-lpcport (in-process server + clients, 64- and 32-bit child processes). Wine's ntdll port test passes without todo (todo_wine removed), om and sync tests pass. Mutants SG_MUTANT_LPC_NO_CONTEXT, SG_MUTANT_LPC_KEEP_WAITING, SG_MUTANT_LPC_NO_SID_CHECK caught.
