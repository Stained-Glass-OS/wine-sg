NOTE: new header include/cryptxml.h (listed in include/Makefile.in), new test directory dlls/cryptxml/tests (configure.ac and configure each gain one WINE_CONFIG_MAKEFILE line; re-run configure in an existing object tree).
Applies to the tree after 5623 (no code dependency). Written from the public documentation of the CRYPT_XML_* structures and functions and the W3C XML-Signature and Canonical XML recommendations. What is implemented: CryptXmlOpenToDecode (CRYPT_XML_BLOB input in UTF-8, UTF-16 LE or BE or auto; flags NO_SERIALIZE and DISABLE_EXTENSIONS accepted; properties MAX_SIGNATURES honoured, MAX_HEAP_SIZE and XML_OUTPUT_CHARSET accepted, others E_INVALIDARG; every Signature element of the document, up to the limit), CryptXmlClose (the document handle frees everything; other handles are a no-op), CryptXmlGetDocContext (any handle of the document), CryptXmlGetSignature, CryptXmlGetReference, CryptXmlGetStatus (document: all signatures together; signature; reference), CryptXmlVerifySignature (RSA PKCS #1 with SHA-1/256/384/512, ECDSA and DSA with the raw r||s value, through bcrypt; the key given, else the KeyInfo's RSA key). Status: unsupported canonicalization or signature algorithms give ERROR_NOT_SUPPORTED_ALGORITHM; a reference gets INTERNAL_REFERENCE for "" and "#id" URIs, ERROR_NOT_RESOLVED when no element has that Id, ERROR_NOT_SUPPORTED_TRANSFORM and ..._ALGORITHM for unknown URIs; KEY_AVAILABLE when the KeyInfo's key imported; SIGNATURE_VALID / ERROR_SIGNATURE_INVALID after a verification.
Gate: cryptxml test (159 checks, both archs): the document context, signatures, references, transforms, digest values, key info, object, the SignedInfo.Encoded bytes against a hand-written canonical form (comment dropped, attributes sorted, single quotes and empty elements normalized, only the used namespace declared in the exclusive form, all in-scope ones in the inclusive form), handles, statuses, UTF-16 input, the signature limit, errors (no signature, DTD, broken XML, no SignedInfo, bad flags), and five verification cases (exclusive, inclusive, declared inclusive but signed exclusive and the reverse, tampered) with the KeyInfo key and with an imported key. Mutants shown failing: SG_MUTANT_C14N_NO_SORT, SG_MUTANT_C14N_ALL_EXCLUSIVE, SG_MUTANT_NO_DTD_BAN, SG_MUTANT_VERIFY_ALWAYS_OK (10, 4, 1 and 12 failures).
NOT done: CryptXmlDigestReference and transform chains (so reference digests are never checked; DIGEST_VALID is never set), CryptXmlOpenToEncode and the encoding half, the transform chain engine handle (the config parameter is ignored), DSA / ECDSA / X.509 KeyInfo items (the signature then reports KEYINFO_NOT_PARSED; a key can still be given to CryptXmlVerifySignature), HMAC signature methods (NTE_BAD_ALGID), canonicalization with comments, xml:* attribute inheritance into an inclusively canonicalized apex element, InclusiveNamespaces PrefixList.
Unverified: every HRESULT other than E_INVALIDARG for malformed input (CRYPT_E_NOT_FOUND for no Signature, HRESULT_FROM_WIN32(ERROR_INVALID_DATA) for a Signature missing a required child, NTE_BAD_SIGNATURE for a signature that does not verify, NTE_BAD_ALGID for an unsupported algorithm); whether CryptXmlClose accepts a signature or reference handle; whether GetStatus on a document handle is the OR of its signatures; the content of the Encoded member of an algorithm (left empty) and of SignedInfo (the canonical form under the declared method); rgTransform as an array of CRYPT_XML_ALGORITHM (the documentation page names the transform info type); the header layout of CRYPT_XML_X509DATA_ITEM, which nothing here fills; the Id attribute names matched for "#id" references (Id, ID, id); the MAX_SIGNATURES property value being passed by pointer.
