- Main's rule (2026-10-23): go through the system's avahi, advertise only while the program holds the registration, never touch firewall/avahi/nsswitch configuration. Done that way: dnsapi.so (mdnsunix.c) dlopens libavahi-client.so.3/libavahi-common.so.3 (no build or package dependency; avahi's client API declared from its documented headers) and is a client of avahi-daemon over D-Bus; no socket of ours, nothing published by us outside an explicit DnsServiceRegister.
- A session = client + simple poll + browser/resolver/entry group; events queued and taken by dnsapi's thread (mdns_wait, 100 ms steps so cancels are seen). Structures without pointers: 32-bit callers share the unix entry points (gate run with MINGW=i686-w64-mingw32-gcc too: PASS).
- Browse: "_svc._tcp[.domain]" (domain default local), V1 and V2 callbacks; each instance (once per interface) is resolved and reported as PTR (Name = service type, pNameHost = instance) + SRV (port, priority/weight 0) + TXT + A/AAAA in the additional section; a removal as a PTR with dwTtl 0; cancel: callback ERROR_CANCELLED, the cancel structure then unknown (ERROR_CANCELLED).
- Resolve: "instance._svc._tcp.domain" -> DNS_SERVICE_INSTANCE (name, host, first address, port, TXT as key/value, interface); failure in the callback (ERROR_TIMEOUT when the responder gives up, DNS_ERROR_RCODE_NAME_ERROR for not found).
- Register: avahi entry group with the instance's name/type/domain/port/TXT (host = this machine unless another name is given; addresses are not published), callback with a copy when established, collision DNS_ERROR_RECORD_ALREADY_EXISTS; one registration per name per process; DnsServiceDeRegister (found by instance name) withdraws it and calls its own callback; the process's end closes the D-Bus connection, which withdraws it too (gate-checked).
- No avahi library: ERROR_SERVICE_DOES_NOT_EXIST; no daemon: ERROR_SERVICE_NOT_ACTIVE (choices; Windows always has its responder).
- Not done: DnsStartMulticastQuery/DnsStopMulticastQuery (generic mDNS record queries), DNS dynamic update (RFC 2136: DnsModifyRecordsInSet/DnsReplaceRecordSet still FIXME-succeed), DnsServiceNotificationRegister.
