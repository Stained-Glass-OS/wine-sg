StdMarshalImpl_DisconnectObject (item 159) was a FIXME returning S_OK without
doing anything. The standard marshaler made by CoGetStandardMarshal(riid, pUnk,
...) now remembers pUnk (holds a reference) and DisconnectObject disconnects
its stub the way CoDisconnectObject does for an object without its own
IMarshal (calling CoDisconnectObject would find this marshaler through the
object's IMarshal only when the object delegates to it, so the stub-manager
work is done directly). A marshaler created without an object (NULL pUnk, the
proxy-side ones) still returns S_OK and does nothing.
Docs: "Releases all connections to an object ... a proxy responds to all
subsequent calls by returning RPC_E_DISCONNECTED or CO_E_OBJNOTCONNECTED".
Wine's existing CoDisconnectObject path yields RPC_S_UNKNOWN_IF (0x800706b5)
for the call after disconnect; this patch does not change that, the gate
requires the same result as CoDisconnectObject.
Risk: the marshaler holds a reference to the object; an object that caches the
marshaler it got from CoGetStandardMarshal would form a cycle.
