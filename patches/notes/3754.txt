CORE review: user32 + win32u keyboard layouts (input switching: every program, Win+H voice typing). Docs: learn.microsoft.com LoadKeyboardLayoutW, LoadKeyboardLayoutEx (undocumented in the SDK; the user32 test_LoadKeyboardLayoutEx todo_wine lines are the spec), UnloadKeyboardLayout, ActivateKeyboardLayout, GetKeyboardLayoutList.
Loaded set: HKCU\Software\Wine\Temporary System Parameters\Keyboard Layout\Loaded ("1".."n" = HKL as DWORD, volatile: lasts for the wineserver session, like the loaded layouts of a logon session). Until a program loads/unloads one, the list is the old implicit one (locale layout + HKLM IMEs); the first Load/Unload materializes it (GetKeyboardLayoutList) and from then on win32u (NtUserGetKeyboardLayoutList) returns the stored set, truncated to the caller's size. The Preload list is not touched.
LoadKeyboardLayoutW: HKL = MAKELONG(language of the KLID, layout id) (04290429 for 00000429; HKLM Layout Id and IME/aliased rules as before), appended unless loaded; KLF_REORDER moves it first; KLF_ACTIVATE activates it; returns the HKL (the old code returned the default layout unless the activation worked). Names that are not <=8 hex digits: 0 + ERROR_INVALID_PARAMETER (GUESS: the error code). LoadKeyboardLayoutEx(hkl, name, flags): NULL hkl returns 0; replaces the slot of hkl (the list keeps its length; a second slot with the same new layout collapses), returns the new HKL; an hkl that is not loaded just loads the layout (GUESS). UnloadKeyboardLayout: ERROR_INVALID_KEYBOARD_HANDLE when the layout is not loaded, is the thread's active one, or is the last one. KLF_SETFORPROCESS, KLF_SUBSTITUTE_OK, KLF_REPLACELANG, KLF_UNLOADPREVIOUS are ignored.
ActivateKeyboardLayout: a layout of another language than the user locale used to be refused (ERROR_CALL_NOT_IMPLEMENTED); it is accepted when it is in the loaded set. Unloaded foreign layouts are still refused. The thread's input language (LOWORD) then drives ANSI conversion (get_input_codepage) as on Windows.
Unverified: WM_INPUTLANGCHANGE's wParam charset for a foreign layout uses win32u's locale data (all-UTF-8 ANSI code pages: 0 until stubs-6c 5217 lands); X11 key tables do not follow a foreign HKL (the layout tables come from the X server). Loads are not shared between wineservers or sessions.
Gate fastb-kbdload (probe checks: load/again/reorder/bad names/short buffer/activation of unloaded and loaded/unload rules/Ex replace, duplicate collapse, unknown hkl/last layout/Preload untouched); 17 mutants caught (LOAD_NOT_STORED LOAD_LANG_IS_LOCALE LOAD_REORDER_IGNORED LOAD_DUPLICATES BADNAME_ACCEPTED LONGNAME_ACCEPTED EX_APPENDS EX_DUP_KEPT UNLOAD_ACTIVE_OK UNLOAD_NOTLOADED_OK UNLOAD_LAST_OK UNLOAD_NOT_REMOVED ACTIVATE_FLAG_IGNORED ACTIVATE_UNLOADED_OK ACTIVATE_LOADED_REFUSED LIST_IGNORED_STORE LIST_SIZE_IGNORED).
