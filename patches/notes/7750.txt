Where the copy goes: the prefix (config dir). Its pages are file-backed and clean (written once), so the kernel can drop them under memory pressure; on tmpfs (server dir, /tmp) or $XDG_RUNTIME_DIR (also tmpfs) they are pinned in memory (swap only) and count against a small filesystem. Cost: the first load of a big unaligned DLL per server lifetime writes its copy to disk once. Cleanup: the file is unlinked as soon as it is created (make_temp_file + unlink), so nothing is left even after a crash; the space is freed when the last mapping goes. Anonymous mappings (shared memory) stay in the server dir (create_temp_file), unchanged: they are written to, and belong in memory.
Fallback: realign-only images map their sections from the file (ntdll's map_file_into_view reads unaligned ones into private memory, as upstream); a shared writable section becomes private to each process (not shared across processes -- only while there is no room).
