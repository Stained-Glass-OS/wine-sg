5213 user32: WINNLSEnableIME, WINNLSGetEnableStatus (gap-CORE 645 and 646; recheck of drafter 7).
Docs: sdk-api winnls32/nf-winnls32-winnlsenableime ("Must be NULL. Specifying a particular IME for each application is not supported"; returns "the previous state of the IME. TRUE if it was enabled before this call").
Both were FIXME stubs returning TRUE. WINNLSEnableIME now keeps the enabled state (process-wide, enabled at start) and returns the previous one; a window handle is refused (FALSE, ERROR_INVALID_PARAMETER); WINNLSGetEnableStatus returns the state it left (same rule for hwnd).
Unverified: the docs' side effect (IME_WINDOWUPDATE to the IME: the conversion windows go away and keyboard messages bypass the IME) is NOT done; only the state is kept, so the call does not hide Wine's IME windows nor stop the IME from receiving keys. The error code for a non-NULL hwnd is a choice (the docs only say it must be NULL). The state is per process here.
