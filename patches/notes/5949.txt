5949 server: a Wow6432Node key directly below \Registry\User\<SID>\Software is not a redirection point (Windows shares HKCU\Software between the views since Windows 7). Before: once a program created HKCU\Software\WOW6432Node\..., every 32-bit program had its own HKCU\Software (qa4: created during Scribus's install). HKLM\Software and the classes keep their redirection.
Gate userhive: with a planted HKCU\Software\WOW6432Node, a 32-bit program's HKCU\Software\... is the shared key and its writes are seen from the 64-bit view, also after a server restart; HKLM\Software\Microsoft in the 32-bit view is still below Wow6432Node. Mutant caught: SG_MUTANT_HKCU_WOW_REDIRECT.
Existing keys below such a node stay where they are (ordinary keys now, as on Windows).
