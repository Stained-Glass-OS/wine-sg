5203 gdi32/win32u/wow64win: logical colour spaces and per-DC ICM state (gap-CORE 216 CreateColorSpaceA, 217 CreateColorSpaceW, 218 DeleteColorSpace, 219 GetColorSpace, 220 SetColorSpace, 228 GetLogColorSpaceA, 229 GetLogColorSpaceW, 230 SetICMProfileA, 231 SetICMProfileW; also SetICMMode, EMF playback of EMR_CREATECOLORSPACEW / EMR_SETICMPROFILEA/W from item 40). UpdateICMRegKeyA/W (232, 233) are not part of this patch.
Docs: learn.microsoft.com/en-us/windows/win32/api/wingdi/ nf-wingdi-createcolorspacew, getlogcolorspacew, setcolorspace ("a handle to the hColorSpace being replaced"), getcolorspace ("regardless of whether color management is enabled"), deletecolorspace, seticmprofilew ("it will be returned by GetICMProfile"). Ground truth in Wine's own tests: gdi32 gdiobj.c test_dc_values (GetColorSpace non-NULL, GetLogColorSpaceA works on it, CreateColorSpaceA(&lcs) succeeds, SelectObject(hdc, hcs) and GetCurrentObject(OBJ_COLORSPACE) == hcs) and icm.c test_SetICMMode (ICM_ON / ICM_OFF stick and ICM_QUERY returns them; a fresh DC is ICM_OFF) - the two todo_wine marks there are removed.
What is new: a GDI object type (NTGDI_OBJ_COLORSPACE 0x0b0000, a Wine value - native uses 0x09 which Wine already uses for bitmaps) holding the LOGCOLORSPACEW; four syscalls NtGdiCreateColorSpace, NtGdiSetColorSpace, NtGdiSetIcmMode, NtGdiSetIcmProfile (win32u.spec, ntgdi.h, wow64win thunks, ARM64EC wrappers, and win32syscalls.h regenerated with tools/make_specfiles, so every later syscall id moves by up to 4: the header diff is large but mechanical); per-DC hColorSpace (default: one system sRGB object, LCS_GM_IMAGES), icm_mode, icm_profile. SaveDC/RestoreDC keep the colour space; ResetDC puts the default back and clears ICM state. SelectObject(hdc, colourspace) is SetColorSpace. GetICMProfile returns the SetICMProfile name before asking the driver.
Nothing is colour converted: ICM_ON only records the state (it did not even work before), the colour space and profile are not applied to drawing. EMF recording of SetICMMode/SetColorSpace/CreateColorSpace is NOT done (playback is). The EMR_SETICMPROFILE embedded profile data (dwFlags 1) is ignored on playback.
Also fixes (header) nothing; wingdi.h's missing LCS_SIGNATURE / ICM_DONE_OUTSIDEDC are defined privately in win32u/ntgdi_private.h.
Unverified: the default colour space's fields on Windows (sRGB with the images intent is assumed), whether Windows rejects a LOGCOLORSPACE with a wrong signature/version/size (this does not; only NULL is refused), whether DeleteColorSpace of the default one fails (here the system object just stays), SetICMProfile on a profile file that does not exist (accepted), GetObject on a colour space handle (returns the LOGCOLORSPACEW; used internally by GetLogColorSpace).
