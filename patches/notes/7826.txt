7826 winex11 sg_embed, explorer systray: a Linux program's full-screen windows on several monitors, framed by the shell.
- sg_embed_attach: a window exactly the size and place of a monitor that draws no frame (_MOTIF_WM_HINTS decorations 0) or cannot be resized (WM_NORMAL_HINTS min = max) is that monitor's full-screen window (mutter's and KWin's "legacy full screen"); checked before get_win_data (no win32u call under its lock).
- A full-screen frame is not maximized: the attach-time "too big for the work area" maximize skips a window full screen already (its _NET_WM_STATE or ours), a maximize request is ignored while full screen or pending, and going full screen clears WS_MAXIMIZE from the frame's style (a maximized pop-up was sized over the whole desktop).
- explorer: the foreground program's full-screen window on a display puts that display's bar behind it, for every display's bar (secondary bars were always topmost) and the main bar too (the foreground window may be on another display); same program = same process, or for framed Linux windows the same X client (X id >> 21). MarkFullscreenWindow on the main display as before.
Found with Devolutions RDM 2026.3 "Open (external)" + "Use multiple monitors" on qa5 (two 1920x1080 heads): RDM -> mstsc.exe (7825) -> sg-mstsc -> sdl-freerdp3 /multimon, X11 (the session's SDL_VIDEODRIVER=x11). sdl-freerdp3 makes one window per monitor, monitor-sized, min=max, the first with _NET_WM_STATE_FULLSCREEN at map, the second with no request (traced: only REMOVE maximized). Framed: first a maximized pop-up 3840 wide, second framed + maximized 3848 wide at x=1916; the second display's bar over the session. Now: frames 0,0-1920,1080 and 1920,0-3840,1080, both bars behind (qa5 screenshot).
Gate test-embedmm (headless two-output sg-compositor, shell desktop over both, stand-in client embedmm-app.c as SDL makes its windows, bars probe embedmm-bars.c): frames exactly each monitor, both full screen, both bars behind. Mutants EMBED_BORDERLESS_WINDOWED, EMBED_FS_MAXIMIZED (winex11), SECOND_BAR_OVER_FULLSCREEN (explorer) caught. Real sdl-freerdp3 repro 3/3 right (was 0/3). linuxembed, embedfs, embedconf, embeddragmax, embedmaxgrab, embedmenu, embedscale, embedselfsize, ownframe, mmtaskbar, taskprogress, multimon, maxmon pass; topbar 1 flaky fail under load, 2/2 pass with and without the change.
Not changed: sg-compositor's own X window manager does nothing with _NET_WM_STATE full-screen requests, and as a Wayland client sdl-freerdp3's second window was not made full screen (reported).
