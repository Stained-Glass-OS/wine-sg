6054 wbemprox (COM-WMI leftovers: polymorphic queries over abstract classes). A SELECT took the queried class's own table only: abstract CIM_ classes without a table (CIM_LogicalDevice, CIM_Setting, CIM_LogicalElement...) gave no instances, and the CIM_ classes that have a table here (CIM_LogicalDisk, CIM_Processor, CIM_DataFile) gave their copies with __CLASS the CIM_ name, where Windows gives the Win32_ subclasses' instances.
query.c:
- create_view(SELECT): after the class's own table, every table whose class derives from it (get_class_parent chain, built-in and stored classes) is added; view->has_own says whether table[0] is the class's own. A CIM_ class with a table of its own and subclass tables skips its own rows (view->skip_own): its table is a copy of a Win32_ one; it stays for the class definition. CIM_DataFile (no subclass table here) is unchanged.
- exec_select_view: each table filled and filtered in turn (tables that lack a property of the condition are left out when there are several; a fill failure skips that table), the results keep their table in view->result_table; map_view_index and get_view_table use it, so __CLASS, __PATH, properties and methods are the row's own class's.
class.c: create_class_only_object uses the class's own table (table[0] only when it is the class's), else WBEM_E_NOT_FOUND as before.
services.c get_object: a class path (no key) whose first enumerated object is a subclass's instance gives the class definition (get_class_definition) instead.
Unknown classes still give an empty result, not WBEM_E_INVALID_CLASS: many Windows classes have no table here and programs tolerate empty results better than errors.
Gate wmipoly (test-wmipoly; JScript through cscript/winmgmts): CIM_Processor gives Win32_Processor instances; CIM_LogicalDevice gives processors and logical disks; WHERE over CIM_LogicalDisk; CIM_Setting gives Win32_Environment; Win32_BaseService gives services; a leaf class only itself; GetObject of CIM_Processor is the CIM_Processor class. 8 PASS.
