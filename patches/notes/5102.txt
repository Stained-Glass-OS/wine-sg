5102 ntdll: NtFlushProcessWriteBuffers (gap-CORE item 446), used by FlushProcessWriteBuffers (the .NET runtime's GC and thread suspension use it to retire per-thread flags).
It was a stub that did nothing. Now it is a process-wide memory barrier: Linux membarrier(MEMBARRIER_CMD_PRIVATE_EXPEDITED) after a one-time MEMBARRIER_CMD_REGISTER_PRIVATE_EXPEDITED; where the kernel lacks it, a page that was written has its protection dropped and restored (the kernel then interrupts the other processors running our threads, which is a barrier on them); on systems without either, only a local full barrier and a WARN.
Docs: learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-flushprocesswritebuffers ("causes the processors that are running threads of the current process to execute a memory barrier").
Unverified: the page-protection fallback was not run (this kernel has membarrier, the gate takes that path); the membarrier syscall numbers for non-x86 are the generic table numbers for x86_64/i386/aarch64/arm only.
