5221 user32: IDataObject::GetDataHere and GetCanonicalFormatEtc of the drag-and-drop data object (gap-CORE 627, 628).
Docs: sdk-api objidl nf-objidl-idataobject-getdatahere (the caller allocates the medium; "if the medium is TYMED_HGLOBAL, this method cannot resize the medium or allocate a new hGlobal"; DV_E_FORMATETC, DV_E_TYMED, STG_E_MEDIUMFULL; punkForRelease NULL) and nf-objidl-idataobject-getcanonicalformatetc (for data that never depends on a device, "copy the input FORMATETC to the output FORMATETC, store a NULL in the ptd member ... and return DATA_S_SAMEFORMATETC").
The data object user32 hands to an OLE drop target for a drag from an X11 program only had GetData. GetDataHere now copies the format's data into the caller's HGLOBAL (STG_E_MEDIUMFULL when it is smaller than the data, DV_E_TYMED when the medium is not an HGLOBAL or has no handle, DV_E_FORMATETC when the object lacks the format, pUnkForRelease NULL); GetCanonicalFormatEtc gives back the input format with ptd NULL and DATA_S_SAMEFORMATETC (DV_E_FORMATETC for a format the object does not have, E_INVALIDARG without output). The FIXMEs are gone. The other methods (SetData, DAdvise, ... E_NOTIMPL / OLE_E_ADVISENOTSUPPORTED, EnumFormatEtc DATADIR_SET) are left as they are: they are the documented answers of a read-only data object.
Unverified: lindex and dwAspect are ignored as QueryGetData already does; native OLE data objects may accept other media (IStream) for GetDataHere, this one is HGLOBAL only like the rest of the object.
Gate test/user32-dataobj-gate.sh (64/32 bit) starts the drag with NtUserMessageCall(NtUserDragDropCall) as the X11 driver does and calls the object from an OLE drop target; mutants DATAOBJ_NOSIZE and DATAOBJ_CANON_OK shown failing it.
