8210 advapi32 SEC-ACL (ledger i0006 object ACEs): SetEntriesInAclW takes the object trustee forms. TRUSTEE_IS_OBJECTS_AND_SID makes an ACCESS_ALLOWED/DENIED/AUDIT object ACE with the GUIDs ObjectsPresent names (the ACL goes to revision 4); TRUSTEE_IS_OBJECTS_AND_NAME without object names is the named account's plain ACE, with names it fails ERROR_NONE_MAPPED (they are directory schema names and there is no directory; quietly dropping the object restriction would widen a grant). An object entry leaves the trustee's plain ACEs alone. Over an old ACL the new one keeps its revision (the old object ACEs were copied into a revision-2 ACL). GetExplicitEntriesFromAclW gives audit ACEs back as SET_AUDIT_SUCCESS/FAILURE and object ACEs as OBJECTS_AND_SID entries (they were NOT_USED_ACCESS with a FIXME). Before, both object forms logged a FIXME and the ACE came out for an uninitialised SID.
