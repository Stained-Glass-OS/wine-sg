6102 shell32 (main 2026-10-24, d0015: TeXstudio from its Start shortcut "aborts with exit code 3" on qa4 -- `wine start /wait ...\TeXstudio.lnk` rc=3, sg-start's ShellExecuteW of the .lnk the same; fine under strace, via rundll32 ShellExec_RunDLL, or the exe started directly; Prism Launcher NO-PROCESS from Start likely the same). Reproduced in my prefix: start /wait on the .lnk returns 3 at once while texstudio.exe keeps running (+process: start.exe's own ShellExecuteEx gave sei.hProcess NULL; NtQueryInformationProcess(nil)). The 3 is start.exe's, not TeXstudio's: WaitForSingleObject(NULL) fails and GetExitCodeProcess(NULL) leaves exitcode undefined. Cause: SHELL_execute runs a .lnk through ShellExecute_FromContextMenu -> shellex_run_context_menu_default -> the shortcut's IContextMenu::InvokeCommand, which ShellExecuteExes the target into a local SHELLEXECUTEINFO and drops its process; and SHELL_execute only copied hInstApp back from sei_tmp. Windows' ShellExecuteEx gives the target's process. Fix: shellex_run_context_menu_default marks (per thread, TLS) that the process is wanted when the caller set SEE_MASK_NOCLOSEPROCESS; ShellLink_InvokeCommand then asks its ShellExecuteEx for it (clearing the mark first, so the target's own launch does not take it) and leaves the handle; shellex takes it into sei->hProcess (or closes it); SHELL_execute copies sei_tmp.hProcess back (and starts sei_tmp.hProcess at NULL). Gate test-linkprocess (a shortcut to the probe's child -- 1.5 s, exit 7 -- run with ShellExecuteEx: a process, the target's, exit 7 after waiting; none unasked; `start /wait child.lnk` exits 7); mutant SG_MUTANT_LINK_NO_PROCESS caught (3 FAIL). shell32 conformance shlexec and shelllink: 0 failures with and without. TeXstudio: start /wait on its .lnk now waits for it. Whether TeXstudio itself also died on qa4 (exit code 4 seen with start /b) is not reproduced here.
