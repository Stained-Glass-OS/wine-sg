5101 ntdll: placeholder compatibility mode (gap-CORE item 367, RtlQueryProcessPlaceholderCompatibilityMode).
The query was a FIXME stub that always answered "application default" and nothing could change it. Now the mode is kept where Windows keeps it, in the PEB (process) and the TEB (thread), and the three missing functions are exported: RtlSetProcessPlaceholderCompatibilityMode, RtlQueryThreadPlaceholderCompatibilityMode, RtlSetThreadPlaceholderCompatibilityMode. A Set returns the previous mode, a mode outside 0..PHCM_MAX gives PHCM_ERROR_INVALID_PARAMETER (-1) and changes nothing.
Docs: learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-rtlsetprocessplaceholdercompatibilitymode, ...rtlqueryprocessplaceholdercompatibilitymode, ...rtlsetthreadplaceholdercompatibilitymode, ...rtlquerythreadplaceholdercompatibilitymode.
Unverified: PHCM_MAX is 3 in Wine's include/ddk/ntifs.h (PHCM_DISGUISE_FULL_PLACEHOLDERS) but 2 on the docs pages; we accept 0..3. There are no placeholder files here, so the mode changes no file attribute. The thread override over the process mode is not consulted by anything yet. A new thread does not inherit the creator's thread mode (starts at 0).
Gate test/ntdll-placeholder-gate.sh (probe test/ntdll-placeholder-probe.c, 64+32 bit: set/previous-value table, ranges, thread vs process vs new thread). Mutants PHCM_RANGE, PHCM_THREAD, PHCM_RET fail it.
