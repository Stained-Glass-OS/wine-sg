CORE review: new server requests (block_input, set_key_write_time, create_transaction, transaction_op) = a new protocol version: FULL REBUILD of all unix modules (ntdll.so, win32u.so, winex11.so..., wineserver) and of the PE modules that include wine/server.h; plus a new win32u syscall (NtUserBlockInput: win32syscalls.h renumbered by tools/make_specfiles, wow64win thunk added). Contents: (1) BlockInput: the desktop remembers the thread that blocked (by id); physical input (hardware origin) is dropped and so is injected input of any other thread, the blocking thread's own SendInput works (the documentation of BlockInput says the same); only the blocker can unblock (STATUS_ACCESS_DENIED -> ERROR_ACCESS_DENIED), blocking again from the same thread is fine, another thread blocking while blocked is ERROR_ACCESS_DENIED, the exit of the blocking thread (even while its object lingers) frees the input; unblocking an unblocked desktop succeeds. The physical-input branch is NOT shown by a mutant here: typing through xdotool into the virtual X display is not reliable (the gate checks it when keys arrive, and prints a note when they do not). Ctrl+Alt+Del does not exist. (2) NtSetInformationKey(KeyWriteTimeInformation) sets the key's last write time (KEY_SET_VALUE needed; read back through RegQueryInfoKey; a later write moves it on); the other classes are as before. (3) Transactions: NtCreateTransaction makes a real object (name, attributes and security as for any named object; the guid, isolation, timeout, description are not kept), NtCommit/RollbackTransaction check TRANSACTION_COMMIT / TRANSACTION_ROLLBACK, a transaction ends once: STATUS_TRANSACTION_ALREADY_COMMITTED / _ABORTED afterwards, other handles STATUS_OBJECT_TYPE_MISMATCH / STATUS_INVALID_HANDLE; ktmw32 CreateTransaction asked for access 0 (FIXME) and now asks TRANSACTION_ALL_ACCESS (0x1f003f). Nothing can enlist in a transaction; GetTransactionId and the rest of ktmw32 stay stubs. Gate fastb-sysproto: 70 checks; 19 mutants caught including BLOCK_HW_NOT_DROPPED (the gate script types keys through XTEST with the pointer on the probe window: there is no window manager, so the X focus is PointerRoot). Conformance 64/32 vs the series-applied base after the full rebuild: ntdll, kernel32, kernelbase, advapi32 identical to base (762/780 kernel32 environment failures in both); secur32 and rpcrt4 identical to a base build; setupapi, ntoskrnl.exe, bcrypt, combase 0 failures.
