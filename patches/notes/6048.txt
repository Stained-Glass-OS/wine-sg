composition_private.h: DEFINE_COMPOSITION_OBJECT moved here; every object's ICompositionObject now has a lazily made property set (the same one each time) and StartAnimation/StopAnimation through animation.c. Objects name their animatable properties in a table (anim_member): visual AnchorPoint, CenterPoint, Offset, Opacity, Orientation, RotationAngle, RotationAngleInDegrees (stored in radians), RotationAxis, Scale, Size; colour brush Color; surface brush Horizontal/VerticalAlignmentRatio; inset clip insets. "Name.X"/".XY"/... animate components. Names not found are looked up in the object's property set; still not found: FIXME, the animation is timed only (so batches end).
New animation.c:
- property sets: entries by name (case-sensitive), Insert replaces value and type, TryGet* says Succeeded/TypeMismatch/NotFound; booleans through ICompositionPropertySet2; entries are animatable.
- easing: linear; cubic bezier (control points kept; x outside 0-1 is E_INVALIDARG), solved by bisection. Key frames without an easing function are linear (Windows' default curve is not documented clearly; linear chosen).
- key frame animations (scalar, vector2/3/4, colour, quaternion): key frames sorted by key (same key replaces; key outside 0-1 E_INVALIDARG), Duration (default 1 s, < 1 ms E_INVALIDARG), DelayTime, IterationBehavior/Count, StopBehavior (default SetToFinalValue), InterpolationColorSpace kept (RGB used). Expression key frames: this.StartingValue/CurrentValue/FinalValue (the starting value) and plain numbers; other expressions hold the previous value with a FIXME. Quaternions slerp, colours lerp per channel.
- expression animations: expression and parameters kept; StartAnimation with one replaces what ran on the property and is a FIXME (not evaluated).
- parameters (Set*Parameter, SetReferenceParameter, Clear*) kept for later.
- running: StartAnimation copies the animation (later changes do not affect it), reads the starting value, and the compositor's notify window steps it every 15 ms (WM_TIMER, started by a posted wake): values are written into the property and compositor_changed asks for a commit (CommitNeeded with a controller). A new animation on the same object and name replaces the old one (LeaveCurrentValue). StopAnimation applies the stop behaviour. Mismatched kinds are E_INVALIDARG.
- batches: a scoped batch collects animations started while open and not suspended (Animation flag for finite, InfiniteAnimation for forever ones); End queues it; Completed handlers are called once, on the compositor's thread, after End and the last of its animations; handlers added after End but before the message loop runs are called (programs subscribe after End). The commit batch (GetCommitBatch) holds what was started since the last commit and ends at the next commit.
- Values are written into the objects' own fields, so getters read animated values (Windows keeps the API value separate); noted, harmless for the programs seen.
