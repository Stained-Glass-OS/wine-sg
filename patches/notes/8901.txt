8901 mf: MFCreateAggregateSource (ledger i0343/i0385: imported by Qt Multimedia apps -- Anki, Kdenlive, MKVToolNix, MusicBrainz Picard, Wireshark, calibre -- which join a camera and a microphone source with it for capture sessions with audio; SG has camera capture sources since vidcap.c). Wine had a spec stub (upstream master too, checked 2026-11-22). Learn documents only the signature, E_INVALIDARG for an empty collection and the camera+microphone use. Own design (dlls/mf/aggregate.c): presentation descriptor = every stream of every source in collection order; each stream gets a descriptor object of its own that forwards IMFAttributes and the media type handler to the real one (so a source reader's SetCurrentMediaType reaches the real stream) and keeps the stream's identifier unless two sources share one (camera and microphone both say 0), then streams are numbered 0..n-1. Streams are wrapped (events re-queued from the real stream, RequestSample forwarded, GetMediaSource = the aggregate). Start: each source gets its own presentation descriptor with the selection mapped, sources with nothing selected are not started; MESourceStarted/Paused/Stopped once all started sources answered (first failure status wins); MEEndOfPresentation once every started source ended; other source events forwarded. Characteristics: live if any is live, seek/pause/skip only if all can, slow seek if any. Shutdown shuts the sources down. Caller behaviour (Qt: MFCreateSourceReaderFromMediaSource on the aggregate, stream index by major type) does not depend on the identifiers.
Gate aggsource (no display; 64/32-bit): two WAV file sources (8 kHz mono, 16 kHz stereo) aggregated; PD 2 streams, ids 0/1, source reader reads both to end of stream, rates map to the right sources, Shutdown.
