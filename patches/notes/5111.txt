5111 ole32: IViewObject::GetColorSet of the data cache (gap-CORE item 509; it logged "stub" and answered E_NOTIMPL).
The docs (learn.microsoft.com/en-us/windows/win32/api/oleidl/nf-oleidl-iviewobject-getcolorset) describe the OLE implementation: it looks at the data it would draw; "If CF_DIB is the drawing format, the palette found in the bitmap is used. For a regular bitmap, no color information is returned. If the drawing format is a metafile, the object handler enumerates the metafile looking for a CreatePalette metafile record. If one is found, the handler uses it as the color set." So: the cache entry Draw would use (same aspect and lindex match, loaded on demand) gives a LOGPALETTE of CoTaskMemAlloc memory from the DIB's colour table (8 bits or fewer), or from the first META_CREATEPALETTE (0xf7) of a Windows metafile / EMR_CREATEPALETTE (49) of an enhanced one; S_FALSE when there is none (true colour DIB, bitmap, a metafile without one); OLE_E_BLANK when no entry with data fits (as Draw, ole2.c:1783 checks it on Windows); DV_E_LINDEX for lindex != -1, DV_E_DVASPECT for an aspect that is not one of the four, E_INVALIDARG for a NULL result pointer (the page lists all of them).
Unverified: the enhanced metafile case is not in the docs text (it applies the metafile rule); an OS/2-style (BITMAPCOREHEADER) DIB gets no palette; the palette of a DIB with biClrUsed 0 and 8 bits has 256 entries; the pvAspect / ptd / target device arguments are not looked at (Draw ignores ptd too).
