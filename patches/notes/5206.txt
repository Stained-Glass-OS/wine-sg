5206 user32: message box Help button (gap-CORE 633 MSGBOX_DlgProc "Help button not supported yet").
Docs: learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-messagebox (MB_HELP: "When the user clicks the Help button or presses F1, the system sends a WM_HELP message to the owner") and ns-winuser-msgboxparamsa (lpfnMsgBoxCallback processes help events).
Clicking IDHELP now builds a HELPINFO (HELPINFO_WINDOW, control id IDHELP, the button's handle, the cursor position) and sends WM_HELP to the dialog, which fills in the box's context help id and calls the callback or the owner, as the F1 path always did. Also fixed: that WM_HELP handler returned 0, so the dialog manager passed the message to the owner a second time (callback and owner both notified; the owner twice); it now reports the message as handled.
Unverified: the contents Windows puts in HELPINFO.MousePos / iContextType for the button (GetCursorPos / HELPINFO_WINDOW assumed), and that F1 reaches the owner once on Windows (the docs say so).
