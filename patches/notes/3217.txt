CORE review: behaviour change
 - MsiRemovePatches used to validate and then return ERROR_PATCH_REMOVAL_UNSUPPORTED for every patch; it now removes: it reinstalls the product (REINSTALL=ALL REINSTALLMODE=omus + the caller's property list) with the listed patches left out while the package is opened (they stay registered until the reinstall succeeded), then forgets them (product Patches value and key, UserData Patches key, the local patch package when the patch targets this product only, as UnpublishProduct does). Errors as documented: INVALID_PARAMETER, UNKNOWN_PRODUCT, PATCH_PACKAGE_OPEN_FAILED/INVALID (patch file), UNKNOWN_PATCH, PATCH_REMOVAL_UNSUPPORTED (the install recorded Uninstallable=0, i.e. AllowRemoval was not 1), PATCH_REMOVAL_DISALLOWED (policy DisablePatchUninstall=1). A call that used to fail now succeeds and changes the installation: only when the caller asks for it. GUESS: that Windows reinstalls with REINSTALLMODE omus (only the files that differ get replaced; nothing in the documentation names the mode).
 - MsiGetLastErrorRecord: was a FIXME returning 0. Now a per-process record (field 0 = the format string, 1 = installer error code, 2 = database path, 3/4 = parameters), cleared by MsiGetLastErrorRecord itself and by every function of the documented list when it starts (MsiOpenDatabase, Commit, OpenView, Import, Export, Merge, GenerateTransform, ApplyTransform, ViewExecute, ViewModify, RecordSetStream, GetSummaryInformation, Get/SetTargetPath, GetSourcePath, Get/SetComponentState, Get/SetFeatureState, GetFeatureCost, GetFeatureValidStates, SetInstallLevel). Set by: open failure 2203 (system error from the storage error) / 2219 (not an installer database), OpenView unknown table 2228, unknown column 2235 (select and where clauses), other syntax errors 2232 (the token the parser stopped at; the specific 2231/2233/2234... messages are not told apart: GUESS), table exists 2204, import file 2215, export file 2214, merge conflicts 2268 (number of tables), transform not an installer transform 2246. Messages and numbers are from the Windows Installer Error Messages table; which function sets which number is only partly documented (the documentation lists the functions, not the numbers). Other documented numbers are not produced (they stay "no record"), custom-action (remote) handles never set it.
 - MsiOpenDatabase on a relative name from a drive root no longer yields "C:\\name" (doubled backslash) in db->path / the DATABASE property.
 - MsiPreviewBillboard returned ERROR_CALL_NOT_IMPLEMENTED and now shows the billboard in a Billboard control of the previewed dialog (NULL removes it); invalid handle ERROR_INVALID_HANDLE; unknown billboard/control, a control that is not a Billboard, no dialog: ERROR_FUNCTION_FAILED (GUESS: the documentation gives no codes).
 - New: the Billboard control type. A dialog that had one logged "unknown control type" and showed nothing. Its Billboard / BBControl rows create Text, Bitmap and Icon sub-controls (other types are refused as the topic says). Driven by EventMapping SetProgress -> Progress: the billboards of the Billboard rows whose Action is the running action and whose feature is being installed are shown in Ordering order, at most one change per second (GUESS: the topic says billboards give a slide show but not the interval); an action with no billboard clears it. Only the reduced/full UI levels create dialogs, so nothing is shown at NONE/BASIC.
