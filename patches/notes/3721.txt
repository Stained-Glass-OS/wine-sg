3721 ncrypt NCryptExportKey NCRYPT_PKCS8_PRIVATE_KEY_BLOB (gap-CLOUD). CORE review: security (private key export).
 - The type "PKCS8_PRIVATEKEY" used to fall through to BCryptExportKey (which does not know it) and any parameter list answered NTE_NOT_SUPPORTED. Now an unencrypted PKCS #8 PrivateKeyInfo (RFC 5208) is produced for RSA (RSAPrivateKey under rsaEncryption), ECDSA/ECDH P-256 and P-384 (ECPrivateKey with the public point under id-ecPublicKey + named curve). It goes through the same export-policy check as every private blob (NCRYPT_ALLOW_PLAINTEXT_EXPORT_FLAG, or ALLOW_EXPORT when wrapped for encrypt_key) and through the existing key transport wrapping; buffers are zeroed after use; size query and NTE_BUFFER_TOO_SMALL behave like the other blob types. The DER was checked with the host openssl (pkey -check accepts it, the public key equals the provider's own public export) and by a DER walk (positive minimal INTEGERs, public key present).
 - NOT done (documented as optional parameters, layout undocumented, nothing to verify against): encrypted PKCS #8 (NCRYPTBUFFER_PKCS_ALG_OID / ALG_PARAM / SECRET) and NCRYPT_PKCS7_ENVELOPE_BLOB (certificate + algorithm). A non-empty parameter list still answers NTE_NOT_SUPPORTED, with a FIXME naming the type. DSA/DH/symmetric keys are not exported as PKCS #8 (NTE_NOT_SUPPORTED). NCryptImportKey of PKCS #8 is not implemented either (separate gap).
