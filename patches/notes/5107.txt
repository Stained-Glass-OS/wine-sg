GetDataHere: the cache is asked first, then the running object's IDataObject::GetDataHere; a handler that is not running answers OLE_E_NOTRUNNING (as GetData and QueryGetData do). Update: a handler that is not running runs the object first (IRunnableObject::Run) and fails the way running fails; ground truth is Wine's ole32/tests/ole2.c, which expects REGDB_E_CLASSNOTREG from IOleObject::Update on a handler of a class that is not registered (it was todo_wine; the mark is removed in this patch). GetRunningClass: S_OK with the handler's class in *lpClsid (it returned S_OK and left the output untouched), E_INVALIDARG for NULL (docs: learn.microsoft.com/en-us/windows/win32/api/objidl/nf-objidl-irunnableobject-getrunningclass, standard values E_INVALIDARG, E_UNEXPECTED, S_OK).
LockRunning: "Most implementations of IRunnableObject::LockRunning call CoLockObjectExternal" (learn.microsoft.com/en-us/windows/win32/api/objidl/nf-objidl-irunnableobject-lockrunning), so the handler's lock is CoLockObjectExternal on the object the container holds (outer IUnknown); it returns that call's result. SetContainedObject: answers S_OK as before (Wine's ole2.c:2957 checks S_OK, from Windows, for a handler not running) with the FIXME removed; the weak-reference effect it describes (docs nf-objidl-irunnableobject-setcontainedobject) is not modeled: the container's reference is not made weak.
