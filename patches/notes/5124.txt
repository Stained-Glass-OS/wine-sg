CORE: integrator must review (ntdll). Fix on top of 5105.

Found by cabinet's XPRESS_HUFF tests (fast-a 3307). The encoder of XPRESS_HUFF could send a match of distance 1 and length 3; its symbol is 256 (offset bits 0, length 0), the same as the end symbol of the stream. The decoder (as in [MS-XCA]) ends at symbol 256 when the input is used up, which is true while the last few symbols are still unread, so an input ending in such a match lost its tail: "qzzzz" decoded to "qz", and 65539 zero bytes to 65536 (the second 64 KiB block is three zeros, a distance 1 length 3 match). The encoder now sends that match as literals. The Plain LZ77 format has no end symbol and is not affected.
Workspace: RtlCompressBuffer(XPRESS, XPRESS_HUFF) never reads the workspace (xpress_compress gets none), so it cannot depend on its contents; the earlier suspicion (a workspace with garbage gave wrong output) was this bug, not the workspace. The gate compresses with a workspace of 0xcc bytes and with a zeroed one and requires identical output.
Gate test/ntdll-xpress-edges-gate.sh (probe test/ntdll-xpress-edges-probe.c, 64+32): 3477 checks: both formats x 7 patterns (zeros, one byte then a run, two bytes then a run, ab ab, random, text, runs of three) x 56 sizes (0-10, 15-26, 31-33, 63-65, 255-260, 1000, four below to three above 64K, 128K and 192K, 196607+, 300000): compress, same output with another workspace, round trip, round trip into an exact-size buffer; the four MS-XCA examples and the Plain LZ77 example byte for byte. Mutants SG_MUTANT_XPRESS_OFF1 (this fix off) plus 5105's XPRESS_HUFF_EOF, XPRESS_HUFF_BLOCK, XPRESS_HUFF_DIST each fail it.
