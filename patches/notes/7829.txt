7829 start: start.exe asked ShellExecuteEx for lpVerb "open". Windows' start uses the type's default verb (lpVerb NULL): a document whose type's default verb is another (shell @="edit"; a suite's own default) gave "Application could not be started, or no application associated" / "ShellExecuteEx failed: File not found" from start "" file.docx. Now NULL: the default verb, else open, as ShellExecute picks.
The title is already consumed by cmd (WCMD_start passes it quoted to start.exe, which takes the first quoted argument as the title): start "" "C:\my doc.x" and start "A title" x pass only the document. Note: testing with `wine cmd /c "start \"\" ..."` from Unix is misleading -- Wine's argv-to-cmdline escapes quotes with backslashes, which cmd keeps; use a .bat.
