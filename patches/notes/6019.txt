6019 gdiplus G-GDIP (ledger i0051, the property-item part): GdipSetPropertyItem (it returned Ok and kept nothing) and GdipRemovePropertyItem (NotImplemented). The properties become a list of the bitmap's own the first time they change (make_property_list: what GdipGetAllPropertyItems gives); Set replaces a property with the same id (the new one goes last), Remove takes it out (PropertyNotFound if absent); metafiles: NotImplemented. Saving a JPEG writes the list into the frame's metadata through the query writer: /app1/ifd/{ushort=id}, the EXIF IFD's tags (0x829a-0x829d, 0x8822-0x8832, 0x9000-0xa4ff) under /exif, the GPS tags (0x0000-0x001f) under /gps; thumbnail and image-structure tags and the IFD pointers are the encoder's. Reading: a JPEG's first metadata block is APP1, whose only item is the IFD reader, so GDI+ listed one property (and nothing for real camera EXIF); a reader with nested IFDs is now flattened into one list of all tags (flatten_metadata), as GDI+ lists them. TIFF: read the same way; the TIFF encoder writes no metadata blocks yet, so a TIFF is saved without them (as before).
Docs: learn.microsoft.com GdipSetPropertyItem/GdipRemovePropertyItem (Image::SetPropertyItem, RemovePropertyItem), Property Item Descriptions (the tag ids); EXIF 2.3 IFD layout.
