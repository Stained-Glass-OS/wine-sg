CORE: integrator must review (rpcrt4 is loaded by everything). CORE review: RPC
3312 rpcrt4: NdrConvert and NdrConvert2, and the byte order of request/response/fault headers (DECISIONS-2 RPC-NDR). Builds on 3310/3311; the gate needs widl 3309.
Implements: new ndr_convert.c, NdrConvert2 (and NdrConvert for the original interpreter parameter list) converting the data of a call in place from the data representation in rpc_msg.DataRepresentation: integers (big-endian), characters (EBCDIC), floating point (IEEE, VAX F/G, IBM short/long, Cray double/single) for base types, simple/conformant/conformant-varying/complex structures, all array and string kinds, encapsulated and non-encapsulated unions, unique/reference/full pointers with their deferred referents (the format of the pointer layout FC_PP and of complex members), context handles, ranges, interface pointer size words, [pipe] chunks. A server converts the [in] parameters and answers in the local representation, a client the [out] ones and the return value (synchronous and asynchronous stubs); the server stubs, NdrServerCall2/NdrAsyncServerCall and both client stubs call it. rpc_message.c: header fields of request/response/fault PDUs are put into the byte order of the label when received and when sent (a server answering with unconverted foreign data), a response gives the client its representation.
Unverified / guesses: the EBCDIC table is code page 37 (the DCE text has no table); the float conversions follow the bit layouts in the "Network Data Representation" chapter of C706 and were not checked against real VAX/Cray/IBM machines (IBM long truncates to 53 bits, values out of range become infinity or zero, no NaN); members of complex structures are walked without aligning them on the wire because the unmarshaller of this rpcrt4 does not align them (standard NDR does), and the encapsulated union discriminant is aligned by the union's increment as the unmarshaller does; interface pointers are the size word and bytes of this rpcrt4's marshaller; USER_MARSHAL is converted only when its wire size is known (walked as the described type), FC_BYTE_COUNT_POINTER, FC_C_BSTRING/SSTRING raise RPC_X_BAD_STUB_DATA; bind, alter_context and the HTTP packets are always little-endian here; the response call id is always 1 (pre-existing).
Gate test/rpcrt4-convert-gate.sh: widl client/server in two processes over ncalrpc and ncacn_ip_tcp (64+32): 16 procedures (base types, structures of all kinds, arrays, strings, unions, pointers, pipe) in 7 representations built by hand (also as raw PDUs on a socket, header included), a stub answering in foreign representations (sync, async, raw response header bytes), and direct NdrConvert/NdrConvert2 calls.
Mutants shown caught: CONVERT_NOSWAP16/32/64, NOEBCDIC, IBMBIAS, VAXWORDS, CRAYBIAS, NODEFER, NOSEEN, NOLAYOUT, MAXCOUNT, DISC, WSTR, CTX, DIRECTION, NOPIPE, HDRBODY, HDRCOMMON, HDRSEND, CLIENTDREP, SERVERDREP, ASYNCCLIENT.
