3214 services.exe (+ svcctl.idl, sechost level 9) gap-A batch, CORE review: 24 items implemented, 8 reserved opnums windows-matches (MS-SCMR), 1 escalate (g/dec/51_services.py). Spec used: [MS-SCMR] v20250811 (Microsoft Open Specifications PDF; IDL appendix and section 3.1.4).
CORE review: behaviour change
 - ChangeServiceConfig(W/A) with lpDependencies == NULL now keeps the dependencies (docs: "Specify NULL if you are not changing the existing dependencies"); before, NULL erased them, so a start-type change dropped a service's dependencies. An empty string still removes them.
 - ChangeServiceConfig with a service type other than own-process fails ERROR_INVALID_PARAMETER ONLY for a service that has a PreferredNode setting (MS-SCMR 3.1.4.11); nothing else can newly fail.
 - ChangeServiceConfig2/QueryServiceConfig2 accept level 9 (SERVICE_CONFIG_PREFERRED_NODE); sechost passes it through. Unknown levels still return ERROR_INVALID_LEVEL (FIXME -> WARN, same result).
 - The ANSI RPC entry points answered ERROR_CALL_NOT_IMPLEMENTED and now work. advapi32 never calls them (it converts and calls the W ones): only remote or foreign clients reach them.
 - svcctl.idl: SC_RPC_CONFIG_INFOW/A gain the preferred-node arm (A also the trigger arm), as in MS-SCMR 2.2.21/2.2.22.
 - Deliberately NOT enforced (new failure paths in installers): delayed auto-start for a service with a group (MS-SCMR 3.1.4.34/35), stop reason validation.
