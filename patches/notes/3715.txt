3715 ws2_32 (gap-CLOUD): CORE review (wineserver sock.c, ntdll/unix socket.c/server.c/file.c; no new server request, so no protocol renumbering; a plain server+ntdll+ws2_32 rebuild is enough).
Implemented:
- WSAIoctl SIO_UDP_CONNRESET + the behaviour behind it. UDP sockets (AF_INET/AF_INET6) get IP_RECVERR/IPV6_RECVERR at creation; the server reads the ICMP error queue on POLLERR (and in recv_socket) and drops everything except "port unreachable". With the option on (the Windows default) the oldest waiting receive fails with STATUS_PORT_UNREACHABLE (WSAECONNRESET), or, with nothing waiting, the next receive does; select/WSAEventSelect see the socket readable meanwhile. With SIO_UDP_CONNRESET FALSE the errors are swallowed. The send-side ECONNREFUSED retry already in ntdll is unchanged; try_recv now retries (STATUS_DEVICE_NOT_READY) on an ECONNREFUSED of a datagram socket instead of returning WSAECONNREFUSED. sock_error ignores ECONNREFUSED on these sockets. New ioctl IOCTL_AFD_WINE_SET_UDP_CONNRESET (306). On a non-UDP socket the ioctl succeeds and does nothing (Windows' result there is NOT verified); in_buff NULL or shorter than a BOOL is WSAEFAULT (guess).
- DisconnectEx(TF_REUSE_SOCKET): new ioctl IOCTL_AFD_WINE_DISCONNECT_REUSE (307): cancels pending sends/receives (STATUS_CANCELLED), shutdown(SHUT_WR) so the peer sees an orderly close, then the server re-runs init_socket() on the same object: new Unix socket, unbound, unconnected, all connection state cleared (WSAENOTCONN on getpeername, SO_CONNECT_TIME -1); WSAEventSelect/non-blocking/timeouts survive. The process that made the call drops its cached Unix fd (server_invalidate_fd_cache). LIMITS: another process that shares the handle keeps its cached old fd until it closes the handle; AcceptEx-only vs ConnectEx-only reuse (TransmitFile docs) is not enforced; SO_RCVBUF/SO_SNDBUF go back to defaults (not verified on Windows). TCP only (not connected = WSAENOTCONN as before).
- WSACancelAsyncRequest (+ the WSAAsyncGetXByY bookkeeping): a request that has not posted yet is cancelled and never posts; one that finished gives WSAEALREADY (last 64 handles remembered), unknown/NULL handles WSAEINVAL. A running getaddrinfo-style lookup is not interrupted, only its message is dropped.
- WSApSetPostRoutine: the routine is used to post the WSAAsyncGetXByY completion messages (PostMessageW when NULL). Not documented anywhere; how Windows uses it for anything else is unknown.
- WPUCompleteOverlappedRequest: returns SOCKET_ERROR with *errno = WSAEINVAL for every socket, which is the documented result for sockets that were not made by WPUCreateSocketHandle; no such socket can exist because ws2_32 has no service provider interface (WPUCreateSocketHandle etc.), see ESCALATE.md. Prototype in ws2spi.h corrected to INT.
- WSAJoinLeaf (UDP multicast): argument checks per the docs (WSAENOTSOCK, WSAEFAULT, WSAEAFNOSUPPORT, WSAEADDRNOTAVAIL for a non multicast address, WSAEINVAL for bad flags, WSAEPROTONOSUPPORT for caller data, WSAEOPNOTSUPP for a non-datagram socket). The result is a DUPLICATE HANDLE of the same socket; unless JL_SENDER_ONLY the socket joins the group. Guesses: that the leaf shares the socket (Windows may make a distinct one); closing the leaf does not leave the group while the original is open; WSAEINVAL for a socket made without WSA_FLAG_MULTIPOINT_* is NOT done (flags are not kept); FD_CONNECT is not posted for a non-blocking join.
- WSAGetQOSByName: WSAENOTSOCK / WSAEFAULT checks, an empty name lists the templates (none exist here); a named template fails with WSAEINVAL. Windows' template names and contents are unknown (no-ground-truth).
Gate fastb-ws2 (3 probes: udp 11 scenarios incl. IPv6, non-blocking, WSAEventSelect, two pending receives, overlapped; reuse x3 plus AcceptEx reuse; misc cancel x200 with exact invariants, post routine, join, qos, wpucomplete). Mutants shown caught (gate result FAIL): UDP_ALWAYS_REPORT (ignores SIO_UDP_CONNRESET FALSE), UDP_NO_WAKE (waiting receive not failed), UDP_NO_POLLIN (select/event select blind), UDP_REPEAT (error reported on every receive), UDP_NO_RECVERR (no error queue), UDP_IOCTL_IGNORED, REUSE_NO_REINIT, REUSE_IGNORED (ws2_32 still shuts down only), JOIN_NO_MEMBERSHIP, CANCEL_NOFLAG, POST_IGNORED.
Conformance ws2_32 (afd, protocol, sock; 64 and 32 bit) ours vs stock: identical failure sets (sock.c select test 4479/4480 flaked once under load on both, passes on rerun; i386 sock.c:1571 family of getsockopt size failures identical on stock).
Idle cost: no thread or timer was added (the cancel list is a plain list under an SRW lock; the server only reads the error queue on POLLERR); the existing threadpool worker of the async lookups ends with its callback.
DEBUG TRAP: the ntdll fd cache (sockets that are connected are cacheable) kept the closed fd of a reused socket until server_invalidate_fd_cache was added; symptom was EPIPE on the first send after the reconnect.
